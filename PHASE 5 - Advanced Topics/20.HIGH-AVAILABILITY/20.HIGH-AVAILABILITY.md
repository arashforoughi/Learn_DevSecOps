```
┌─────────────────────────────────────────┐
│         VAULT HA CLUSTER (3 nodes)      │
├─────────────────────────────────────────┤
│                                         │
│  ┌──────────┐  ┌──────────┐            │
│  │ Vault-1  │  │ Vault-2  │            │
│  │ (Leader) │  │ (Standby)│            │
│  └─────┬────┘  └────┬─────┘            │
│        │             │                  │
│        │    ┌────────┘                  │
│        │    │                           │
│        │    ▼                           │
│        │  ┌──────────┐                  │
│        │  │ Vault-3  │                  │
│        │  │ (Standby)│                  │
│        │  └─────┬────┘                  │
│        │        │                       │
│  ┌─────┴────────┴──────┐               │
│  │  Shared Storage     │               │
│  │  (Consul, S3, etc)  │               │
│  └────────┬────────────┘               │
│           │                            │
│    Only leader stores data             │
│    All nodes read from storage         │
│                                         │
│  If leader dies:                       │
│  ✅ Standby promotes to leader         │
│  ✅ No secrets lost                    │
│  ✅ No downtime                        │
│                                         │
└─────────────────────────────────────────┘
```

### Configure Vault HA with Consul Backend

Update `vault.hcl` to use Consul as storage backend:

```hcl
# /etc/vault/vault.hcl - HA Configuration

listener "tcp" {
  address       = "0.0.0.0:8200"
  tls_cert_file = "/etc/vault/tls/vault.crt"
  tls_key_file  = "/etc/vault/tls/vault.key"
}

# HA Storage Backend (Consul)
storage "consul" {
  address = "consul.devsecops.com:8500"
  path    = "vault/"
  service = "vault"
  scheme  = "https"
}

# HA Listener (for cluster communication)
ha_storage "consul" {
  address = "consul.devsecops.com:8500"
  path    = "vault-ha/"
}

ui = true
log_level = "info"
```

### Deploy 3 Vault Nodes

```bash
# On sec-vault-01, sec-vault-02, sec-vault-03:

# Node 1 (Leader)
vm# CONSUL_HTTP_ADDR=https://consul.devsecops.com:8500 \
    vault server -config=/etc/vault/vault.hcl

# Node 2 & 3 (Standbys) - same command
# They auto-join the cluster via Consul
```

### Initialize Cluster

```bash
# Initialize ONCE (on any node)
vault operator init \
  -key-shares=5 \
  -key-threshold=3

# Unseal all 3 nodes (same keys work on all)
vault operator unseal  # Run on each node
vault operator unseal
vault operator unseal
```

### Verify HA Status

```bash
# Check leader
vault status

# Expected output:
→ HA Enabled       true
→ HA Cluster       https://vault-1.devsecops.com:8201
→ HA Mode          leader (or standby)

# Check all nodes
vault write sys/replication/status
```

## 20.3 Database High Availability

### PostgreSQL Master-Slave Replication

Current setup (single database):

```bash
# Single database on postgres container
# If it dies: ❌ Data lost
# If it's slow: ❌ Everything slow
```

HA Setup (master-slave):

```
┌─────────────────────────────────────────┐
│    POSTGRESQL HA (Master-Slave)         │
├─────────────────────────────────────────┤
│                                         │
│  ┌──────────────┐     ┌──────────────┐ │
│  │ Primary Node │     │ Standby Node │ │
│  │ (sec-db-01)  │────▶│ (sec-db-02)  │ │
│  │              │     │              │ │
│  │ Writes here  │     │ Replicated   │ │
│  │ Reads here   │     │ Read-only    │ │
│  └──────┬───────┘     └──────┬───────┘ │
│         │                    │         │
│  ┌──────┴────────────────────┴──────┐  │
│  │     Clients (GitLab, Authentik,  │  │
│  │     SonarQube, DefectDojo)       │  │
│  │     Read from standby if primary │  │
│  │     is slow                      │  │
│  └──────────────────────────────────┘  │
│                                         │
│  If primary dies:                       │
│  ✅ Promote standby to primary          │
│  ✅ No data loss                        │
│  ✅ Automatic with tools like Patroni  │
│                                         │
└─────────────────────────────────────────┘
```

### Configure PostgreSQL Replication

**Primary node (sec-db-01):**

```yaml
# docker-compose.yml - Primary

postgres:
  image: postgres:14
  environment:
    POSTGRES_REPLICATION_MODE: master
    POSTGRES_REPLICATION_USER: replicator
    POSTGRES_REPLICATION_PASSWORD: repl_password
  volumes:
    - ./postgres_data:/var/lib/postgresql/data
  ports:
    - "5432:5432"
```

**Standby node (sec-db-02):**

```yaml
# docker-compose.yml - Standby

postgres:
  image: postgres:14
  environment:
    POSTGRES_REPLICATION_MODE: slave
    POSTGRES_MASTER_SERVICE: postgres-primary
    POSTGRES_REPLICATION_USER: replicator
    POSTGRES_REPLICATION_PASSWORD: repl_password
  volumes:
    - ./postgres_standby:/var/lib/postgresql/data
  depends_on:
    - postgres-primary
```

### Use Patroni for Automatic Failover

Patroni manages HA PostgreSQL clusters:

```bash
# Install Patroni on both nodes
pip install patroni psycopg2

# Create patroni.yml on primary
cat > /etc/patroni/patroni.yml << 'EOF'
scope: devsecops-postgresql
name: postgresql-1

restapi:
  listen: 0.0.0.0:8008
  connect_address: postgres-1.devsecops.com:8008

consul:
  host: consul.devsecops.com:8500

postgresql:
  data_dir: /var/lib/postgresql/data
  pgctl: /usr/lib/postgresql/14/bin/pg_ctl
  pg_ctl_timeout: 300

  parameters:
    max_connections: 500
    shared_buffers: 256MB

  recovery_conf:
    restore_command: cp /var/lib/postgresql/wal_archive/%f %p

  create_replica_methods:
    - basebackup

EOF

# Start Patroni
patroni /etc/patroni/patroni.yml
```

## 20.4 Redis High Availability

### Redis Sentinel (Automatic Failover)

```
┌──────────────────────────────────────────┐
│      REDIS HA WITH SENTINEL              │
├──────────────────────────────────────────┤
│                                          │
│  ┌─────────────────────────────────┐    │
│  │ Redis Sentinel (3 instances)    │    │
│  │ - Monitor master & replicas     │    │
│  │ - Detect failures               │    │
│  │ - Promote replica if needed     │    │
│  │ - Notify clients of changes     │    │
│  └─────────────────────────────────┘    │
│           │         │         │          │
│           ▼         ▼         ▼          │
│  ┌──────────────┐ ┌──────────────┐      │
│  │ Redis Master │ │ Redis Replica│      │
│  │ (Writes)     │ │ (Reads)      │      │
│  └──────┬───────┘ └──────┬───────┘      │
│         │                │              │
│         └────────┬───────┘              │
│                  │                      │
│         ┌────────▼────────┐             │
│         │   Clients       │             │
│         │ (Connect via    │             │
│         │  Sentinel)      │             │
│         └─────────────────┘             │
│                                          │
│  If master dies:                         │
│  ✅ Sentinel detects (< 1 second)       │
│  ✅ Promotes replica to master          │
│  ✅ Clients auto-reconnect              │
│  ✅ Zero downtime (typically)           │
│                                          │
└──────────────────────────────────────────┘
```

### Redis Sentinel Configuration

```bash
# redis-sentinel.conf

port 26379
daemonize yes
logfile "/var/log/redis/sentinel.log"

# Monitor master redis
sentinel monitor mymaster 10.0.2.30 6379 2
# 2 sentinels must agree on failure

# Failover timeout (30 seconds)
sentinel failover-timeout mymaster 30000

# Notification script (optional)
sentinel notification-script mymaster /etc/redis/notify.sh
```

### HA Setup (2+ HAProxies with Keepalived)

```
┌────────────────────────────────────────────┐
│    HAProxy HA WITH KEEPALIVED             │
├────────────────────────────────────────────┤
│                                            │
│  ┌──────────────────┐  ┌────────────────┐ │
│  │ HAProxy Primary  │  │ HAProxy Backup │ │
│  │ (sec-edge-01)    │  │ (sec-edge-02)  │ │
│  └────────┬─────────┘  └────────┬───────┘ │
│           │                     │         │
│  ┌────────┴─────────────────────┴──────┐  │
│  │    Keepalived (Monitors both)       │  │
│  │    Owns Virtual IP (VIP):           │  │
│  │    10.0.2.100 (internal)            │  │
│  │    203.0.113.1 (external)           │  │
│  └─────────────────┬────────────────────┘ │
│                    │                      │
│         ┌──────────▼──────────┐           │
│         │   Clients Connect   │           │
│         │   to VIP (not to    │           │
│         │   specific node)    │           │
│         └─────────────────────┘           │
│                                            │
│  If primary fails:                         │
│  ✅ Keepalived detects                    │
│  ✅ VIP moves to backup                   │
│  ✅ Traffic continues to VIP              │
│  ✅ No client configuration needed        │
│                                            │
└────────────────────────────────────────────┘
```

### Install Keepalived

```bash
# On sec-edge-01 (primary)
vm# apt install keepalived

# /etc/keepalived/keepalived.conf
vrrp_script check_haproxy {
  script "systemctl is-active haproxy"
  interval 2
  weight -20
}

vrrp_instance VI_1 {
  state MASTER
  interface eth0
  virtual_router_id 51
  priority 100
  advert_int 1
  
  authentication {
    auth_type PASS
    auth_pass keepalived123
  }
  
  virtual_ipaddress {
    10.0.2.100
    203.0.113.1
  }
  
  track_script {
    check_haproxy
  }
}

# On sec-edge-02 (backup)
# Same config but:
# state BACKUP
# priority 99
```

## 20.7 Validation & Monitoring

### Health Checks

```bash
# Check Vault cluster status
vault operator raft autopilot state

# Expected:
→ Healthy: true
→ FailureTolerance: 1 (can lose 1 node)
→ Servers: 3 (all 3 running)

# Check database replication lag
psql -c "SELECT NOW() - pg_last_xact_replay_timestamp() AS replication_lag;"

# Check Redis Sentinel status
redis-cli -p 26379 SENTINEL masters
redis-cli -p 26379 SENTINEL slaves mymaster
```

### Prometheus Alerting

```yaml
# prometheus-rules.yml

groups:
  - name: ha_monitoring
    rules:
      - alert: VaultClusterUnhealthy
        expr: vault_core_handle_login_request == 0
        for: 5m
        annotations:
          summary: "Vault cluster unhealthy"
          
      - alert: PostgresReplicationLagTooHigh
        expr: pg_replication_lag_seconds > 5
        for: 2m
        annotations:
          summary: "PostgreSQL replication lag > 5 seconds"
          
      - alert: RedisFailoverNeeded
        expr: redis_sentinel_simulate_failure_alarms > 0
        for: 1m
        annotations:
          summary: "Redis failover needed"
```

## 20.8 Disaster Recovery Testing

Test HA failover procedures:

```bash
# Test Vault failover
1. Kill leader node: killall vault
   → Standby should promote to leader
   → Check: vault status (should show new leader)

# Test Database failover
1. Stop primary: systemctl stop postgresql
   → Standby should promote
   → Check: psql -c "SELECT pg_is_in_recovery();" should return false

# Test HAProxy failover
1. Kill primary HAProxy: systemctl stop haproxy
   → Keepalived moves VIP to backup
   → Check: ip addr (VIP should be on backup now)
   → Clients continue to connect via VIP

# Test Redis failover
1. Kill master Redis: redis-cli SHUTDOWN
   → Sentinel promotes replica
   → Check: redis-cli ROLE (should return master)
```

## 20.9 Chapter Summary

|Component|HA Strategy|RPO|RTO|
|---|---|---|---|
|**Vault**|Clustering (HA mode)|0 (sync)|< 1s|
|**Database**|Master-Slave + Patroni|0 (sync)|1-5s|
|**Cache**|Sentinel + Replicas|< 1s|< 1s|
|**LB**|Keepalived + VIP|N/A|< 1s|

**RPO** = Recovery Point Objective (how much data can you lose)  
**RTO** = Recovery Time Objective (how long until recovery)

💡 **Key Takeaway — Eliminate Single Points of Failure:**

Before HA:

- ❌ One node dies = complete outage
- ❌ Manual intervention required
- ❌ Data loss possible

After HA:

- ✅ N-1 nodes can fail (quorum-based)
- ✅ Automatic failover (seconds)
- ✅ Zero data loss (sync replication)
