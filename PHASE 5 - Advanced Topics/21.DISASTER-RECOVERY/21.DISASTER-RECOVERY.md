## 21.1 Disaster Recovery Tiers

### Tier 1: Backup Only (Cold DR)

```
Disaster occurs
     ↓
Restore from backup (manual)
     ↓
Rebuild infrastructure
     ↓
Restore data
     ↓
Repoint DNS
     ↓
Recovery time: 4-8 HOURS (❌ Unacceptable for production)
```

### Tier 2: Replication + Failover (Warm DR)

```
Disaster occurs
     ↓
HA system detects
     ↓
Automatic failover
     ↓
Recovery time: 1-5 MINUTES (✅ Acceptable)
     
Plus: Backup as additional safeguard
```

### Tier 3: Multi-Region (Hot DR)

```
Disaster in Region A
     ↓
Automatic failover to Region B
     ↓
Recovery time: < 1 SECOND (✅ Zero downtime)

Requires: Full duplication across regions
```

## 21.3 Vault Backup & Restore

### Automated Vault Backups

```bash
#!/bin/bash
# /opt/vault/backup.sh - Hourly backup script

BACKUP_DIR=/mnt/backups/vault
DATE=$(date +%Y-%m-%d_%H-%M-%S)

# Create snapshot
VAULT_TOKEN=$ROOT_TOKEN vault read -format=json \
  sys/storage/raft/snapshot > $BACKUP_DIR/snapshot-$DATE.json

# Encrypt backup
gpg --symmetric \
  --cipher-algo AES256 \
  --passphrase-file /etc/vault/backup-password \
  $BACKUP_DIR/snapshot-$DATE.json

# Upload to S3 (offsite)
aws s3 cp \
  $BACKUP_DIR/snapshot-$DATE.json.gpg \
  s3://devsecops-backups/vault/

# Keep only 24 hourly backups
find $BACKUP_DIR -name "snapshot-*.json.gpg" -mtime +1 -delete

# Log backup
echo "$(date): Vault backup completed - snapshot-$DATE.json.gpg" >> /var/log/backup.log
```

### Restore from Vault Backup

```bash
# In case of Vault data loss:

# 1. Stop Vault
systemctl stop vault

# 2. Clear storage
rm -rf /var/lib/vault/data/*

# 3. Restore from backup
gpg --decrypt \
  --passphrase-file /etc/vault/backup-password \
  /mnt/backups/vault/snapshot-2025-01-15_12-00-00.json.gpg | \
  vault operator raft snapshot restore - 

# 4. Unseal Vault
vault operator unseal

# 5. Verify
vault status
```

## 21.4 Database Backup & Restore

### PostgreSQL Backup Strategy

```bash
#!/bin/bash
# /opt/postgres/backup.sh - Daily backup

BACKUP_DIR=/mnt/backups/postgres
DATE=$(date +%Y-%m-%d)

# Full backup
pg_basebackup -h localhost \
  -D $BACKUP_DIR/full-$DATE \
  -Ft -z -P

# Continuous WAL archiving (for point-in-time recovery)
mkdir -p /var/lib/postgresql/wal_archive
chmod 700 /var/lib/postgresql/wal_archive

# In postgresql.conf:
# archive_mode = on
# archive_command = 'cp %p /var/lib/postgresql/wal_archive/%f'

# Upload to S3
aws s3 sync $BACKUP_DIR/ s3://devsecops-backups/postgres/

# Keep 30 daily backups locally
find $BACKUP_DIR -name "full-*" -mtime +30 -delete
```

### PostgreSQL Point-in-Time Recovery (PITR)

```bash
# Recover database to specific point in time

# 1. Stop PostgreSQL
systemctl stop postgresql

# 2. Remove current data
rm -rf /var/lib/postgresql/data/*

# 3. Restore full backup
tar -xzf $BACKUP_DIR/full-2025-01-14.tar.gz \
  -C /var/lib/postgresql/data

# 4. Create recovery.conf
cat > /var/lib/postgresql/data/recovery.conf << 'EOF'
restore_command = 'cp /var/lib/postgresql/wal_archive/%f %p'
recovery_target_timeline = 'latest'
recovery_target_time = '2025-01-15 14:30:00'  # Recover to this time
recovery_target_inclusive = true
EOF

# 5. Start PostgreSQL (will recover)
systemctl start postgresql

# PostgreSQL replays WAL files until target time
# Data is consistent as of 2025-01-15 14:30:00
```

## 21.5 Infrastructure Code Backup (Git)

### Git Repositories Are Your Backup

```bash
# All infrastructure code is in Git:
# ├─ Packer HCL templates
# ├─ OpenTofu code
# ├─ Ansible playbooks
# ├─ Kubernetes manifests
# ├─ CI/CD configurations
# └─ Documentation

# Backup entire Git history:
cd /opt/git-repos
for repo in *.git; do
  git clone --mirror $repo \
    s3://devsecops-backups/git/$repo
done

# Result: Complete history backed up
# Can rebuild entire infrastructure from Git
```

### Offsite Git Backups

```bash
# Push to multiple remotes

git remote add backup3 s3://bucket/git-backup

# Push to all

git push backup2 --all
git push backup3 --all
```

## 21.6 Container Registry Backup

### Harbor Export

```bash
#!/bin/bash
# /opt/harbor/backup.sh - Daily harbor backup

BACKUP_DIR=/mnt/backups/harbor
DATE=$(date +%Y-%m-%d)

# Export all images from Harbor
curl -u admin:$HARBOR_PASSWORD \
  https://harbor.devsecops.com/api/v2/projects?page_size=100 | \
  jq -r '.[] | .name' | while read project; do
    
    curl -u admin:$HARBOR_PASSWORD \
      https://harbor.devsecops.com/api/v2/projects/$project/repositories | \
      jq -r '.[] | .name' | while read repo; do
      
        echo "Pulling $project/$repo..."
        docker pull harbor.devsecops.com/$project/$repo:latest
        docker save harbor.devsecops.com/$project/$repo:latest | \
          gzip > $BACKUP_DIR/$project-$repo-$DATE.tar.gz
      done
  done

# Upload to S3
aws s3 sync $BACKUP_DIR/ s3://devsecops-backups/harbor/

# Cleanup old backups (keep 7 days)
find $BACKUP_DIR -name "*.tar.gz" -mtime +7 -delete
```

### Restore Images from Backup

```bash
# Restore all images from backup
for backup_file in /mnt/backups/harbor/*.tar.gz; do
  echo "Restoring $backup_file..."
  docker load -i $backup_file
  
  # Push to Harbor
  docker push $(tar -tzf $backup_file | head -1)
done
```

## 21.7 Disaster Recovery Runbook

### Complete DR Procedure

**Time: 2025-01-15 14:00:00 - PRIMARY DATACENTER DESTROYED**

#### Phase 1: Assessment (15 minutes)

```bash
# 1. Confirm disaster
STATUS=$(curl -s https://primary.devsecops.com/health || echo "DEAD")
if [ "$STATUS" = "DEAD" ]; then
  SEVERITY="CRITICAL"
  ACTION="ACTIVATE_DR"
fi

# 2. Contact on-call team
- Page primary on-call engineer
- Page backup on-call engineer  
- Notify operations team

# 3. Activate war room
- Open incident in PagerDuty
- Create war room in Slack: #incident-response
- Begin live updating status
```

#### Phase 2: Failover (30 minutes)

```bash
# 1. Promote DR infrastructure
# Change DNS to point to DR region
aws route53 change-resource-record-sets \
  --hosted-zone-id Z123ABC \
  --change-batch '{
    "Changes": [{
      "Action": "UPSERT",
      "ResourceRecordSet": {
        "Name": "api.devsecops.com",
        "Type": "A",
        "TTL": 60,
        "ResourceRecords": [{"Value": "203.0.113.50"}]  # DR IP
      }
    }]
  }'

# 2. Start DR services
ansible-playbook playbooks/start-dr-services.yml

# 3. Restore databases from latest backup
cd /mnt/backups/postgres
tar -xzf full-$(date -d yesterday +%Y-%m-%d).tar.gz \
  -C /var/lib/postgresql/data

# 4. Start services
systemctl start postgresql vault haproxy nginx
```

#### Phase 3: Validation (15 minutes)

```bash
# 1. Health checks
./validate-chapter-13.sh  # GitLab
./validate-chapter-14.sh  # SonarQube
./validate-chapter-15.sh  # Harbor
./validate-chapter-20.sh  # HA systems

# 2. Data verification
curl https://api.devsecops.com/health
# Should return: {"status": "healthy"}

# 3. Database verification
psql -c "SELECT COUNT(*) FROM users;"
# Should show expected number of users

# 4. Git repositories
git clone https://gitlab.devsecops.com/root/myapp.git
# Should succeed
```

#### Phase 4: Communication (Ongoing)

```bash
# Update status every 15 minutes in #incident-response
[14:00] Disaster confirmed in primary region
[14:15] DR failover initiated
[14:45] DR validation complete
[14:50] Traffic switched to DR
[15:00] Service restored - investigating root cause
```
