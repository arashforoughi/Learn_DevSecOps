## 27.1 Observability Architecture

### Three Pillars of Observability

```
┌─────────────────────────────────────────────────────┐
│         OBSERVABILITY (Three Pillars)               │
├─────────────────────────────────────────────────────┤
│                                                     │
│  PILLAR 1: LOGGING (ELK Stack)                     │
│  ├─ All application logs → Logstash                │
│  ├─ Stored in Elasticsearch                        │
│  ├─ Searched in Kibana                             │
│  └─ Debug issues by searching logs                 │
│                                                     │
│  PILLAR 2: METRICS (Prometheus + Grafana)          │
│  ├─ CPU, memory, disk from all nodes              │
│  ├─ Application metrics (response time, errors)    │
│  ├─ Scraped by Prometheus every 15 seconds        │
│  └─ Visualized in Grafana dashboards              │
│                                                     │
│  PILLAR 3: TRACING (Jaeger)                       │
│  ├─ Follow request through microservices          │
│  ├─ See where time is spent                       │
│  ├─ Find bottlenecks                              │
│  └─ Performance optimization data                 │
│                                                     │
│  ALERTING (AlertManager)                           │
│  ├─ Fires when metrics exceed thresholds          │
│  ├─ Notifies via Slack, email, PagerDuty         │
│  └─ Automatic incident creation                   │
│                                                     │
└─────────────────────────────────────────────────────┘
```

## 27.2 ELK Stack (Logging)

### Deploy Elasticsearch

```bash
# On sec-obs-01 (10.0.2.30)

docker run -d \
  --name elasticsearch \
  -e discovery.type=single-node \
  -e "ES_JAVA_OPTS=-Xms512m -Xmx512m" \
  -p 9200:9200 \
  -v elastic_data:/usr/share/elasticsearch/data \
  docker.elastic.co/elasticsearch/elasticsearch:8.5.0
```

### Deploy Logstash (Log Processing)

```yaml
# logstash.conf
input {
  # Collect logs from all services
  syslog {
    port => 5000
    codec => json
  }
  
  # Kubernetes pod logs
  kubernetes {
    kubernetes_url => "https://kubernetes.default.svc"
    ca_file => "/var/run/secrets/kubernetes.io/serviceaccount/ca.crt"
  }
}

filter {
  # Parse JSON logs
  json {
    source => "message"
  }
  
  # Add timestamp
  date {
    match => [ "timestamp", "ISO8601" ]
  }
}

output {
  # Send to Elasticsearch
  elasticsearch {
    hosts => ["elasticsearch:9200"]
    index => "logs-%{+YYYY.MM.dd}"
  }
}
```

### Deploy Kibana (Visualization)

```bash
docker run -d \
  --name kibana \
  -e ELASTICSEARCH_HOSTS=http://elasticsearch:9200 \
  -p 5601:5601 \
  docker.elastic.co/kibana/kibana:8.5.0

# Access: http://10.0.2.30:5601
```

## 27.3 Prometheus & Grafana (Metrics)

### Deploy Prometheus

```yaml
# prometheus.yml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

alerting:
  alertmanagers:
    - static_configs:
        - targets:
            - alertmanager:9093

rule_files:
  - 'alert_rules.yml'

scrape_configs:
  # Scrape Kubernetes nodes
  - job_name: 'kubernetes-nodes'
    kubernetes_sd_configs:
      - role: node
    scheme: https
    tls_config:
      ca_file: /var/run/secrets/kubernetes.io/serviceaccount/ca.crt

  # Scrape pods
  - job_name: 'kubernetes-pods'
    kubernetes_sd_configs:
      - role: pod
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true

  # Scrape HAProxy
  - job_name: 'haproxy'
    static_configs:
      - targets: ['10.0.2.25:8404']

  # Scrape Vault
  - job_name: 'vault'
    static_configs:
      - targets: ['10.0.2.13:8200']

  # Scrape etcd
  - job_name: 'etcd'
    static_configs:
      - targets: ['10.0.2.20:2379', '10.0.2.21:2379', '10.0.2.22:2379']
```

## 27.4 Key Metrics to Monitor

### System Metrics

```
CPU Usage per Node
├─ Alert if > 80% for 5 minutes
├─ Alert if > 90% for 2 minutes
└─ Critical if > 95%

Memory Usage per Node
├─ Alert if > 85% for 5 minutes
└─ Critical if > 95%

Disk Usage per Node
├─ Alert if > 80% full
├─ Alert if growth rate unsustainable
└─ Critical if > 95% full

Network I/O
├─ Monitor bandwidth usage
├─ Alert on unexpected traffic spikes
└─ Check for DDoS patterns
```

### Application Metrics

```
Request Latency (p50, p95, p99)
├─ Alert if p95 > 1 second (SLA)
├─ Alert if p99 > 5 seconds
└─ Critical if > 10 seconds

Error Rate
├─ Alert if > 0.5%
├─ Alert if > 1%
└─ Critical if > 5%

Pod Restart Count
├─ Alert if pod restarting frequently
├─ Indicates crashing containers
└─ Requires investigation

Service Availability
├─ Monitor health checks
├─ Alert on service down
└─ Critical: multiple services down
```

### Kubernetes Metrics

```
Node Status
├─ Alert if node NotReady
├─ Alert if node pressure (memory, disk, PID)
└─ Critical: control plane node down

Pod Status
├─ Alert if pod CrashLoopBackOff
├─ Alert if pod Pending > 5 minutes
└─ Critical: unable to schedule pods

Etcd Health
├─ Alert if etcd member down
├─ Alert if replication lag > 5 seconds
└─ Critical: quorum lost
```

## 27.5 Alert Rules

```yaml
# alert_rules.yml
groups:
  - name: system_alerts
    rules:
      - alert: NodeMemoryHigh
        expr: node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes < 0.15
        for: 5m
        annotations:
          summary: "Node {{ $labels.node }} memory usage high"
          description: "Only {{ $value | humanizePercentage }} memory available"

      - alert: NodeDiskHigh
        expr: node_filesystem_avail_bytes / node_filesystem_size_bytes < 0.15
        for: 5m
        annotations:
          summary: "Node {{ $labels.node }} disk usage high"

      - alert: PodCrashLooping
        expr: increase(kube_pod_container_status_restarts_total[30m]) > 5
        annotations:
          summary: "Pod {{ $labels.pod }} is crash looping"

      - alert: KubeletDown
        expr: up{job="kubelet"} == 0
        for: 5m
        annotations:
          summary: "Kubelet on {{ $labels.node }} is down"

      - alert: EtcdMemberDown
        expr: up{job="etcd"} == 0
        for: 5m
        annotations:
          summary: "etcd member {{ $labels.instance }} is down"
```

## 27.6 Distributed Tracing (Jaeger)

### Deploy Jaeger

```bash
docker run -d \
  --name jaeger \
  -e COLLECTOR_ZIPKIN_HOST_PORT=:9411 \
  -p 6831:6831/udp \
  -p 16686:16686 \
  jaegertracing/all-in-one:latest

# Access: http://10.0.2.30:16686
```

### Instrument Application

```python
# Flask with Jaeger tracing
from jaeger_client import Config

def init_tracer(service_name):
    config = Config(
        config={
            'sampler': {
                'type': 'const',
                'param': 1,
            },
            'logging': True,
            'local_agent': {
                'reporting_host': 'jaeger',
                'reporting_port': 6831,
            },
        },
        service_name=service_name,
        validate=True,
    )
    return config.initialize_tracer()

tracer = init_tracer('myapp')

@app.route('/api/users/<user_id>')
def get_user(user_id):
    with tracer.start_active_span('get_user') as scope:
        span = scope.span
        span.set_tag('user.id', user_id)
        
        # Fetch user from database
        user = db.get_user(user_id)
        
        return jsonify(user)
```

## 27.7 SIEM Integration (Wazuh)

### Deploy Wazuh Agent

On each node to collect security events:

```bash
# Install Wazuh agent
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | apt-key add -
apt-get install -y wazuh-agent

# Configure agent
sed -i "s/<manager_ip>/${WAZUH_MANAGER_IP}/g" /var/ossec/etc/ossec.conf

# Start agent
systemctl enable wazuh-agent
systemctl start wazuh-agent

# Wazuh collects:
# ✅ File integrity monitoring (FIM)
# ✅ System configuration changes
# ✅ Failed login attempts
# ✅ Malware detection
# ✅ Intrusion detection (HIDS)
# ✅ Container activity
```

## 27.9 Retention Policies

### Log Retention

```
Hot Tier (0-7 days)
├─ Searchable in Kibana
├─ All logs indexed
└─ Fast queries

Warm Tier (7-30 days)
├─ Searchable but slower
├─ Compressed storage
└─ Lower cost

Cold Tier (30+ days)
├─ Archive storage
├─ Restore only if needed
└─ Compliance retention
```

### Metrics Retention

```
Prometheus (2 weeks default)
├─ Configurable retention
├─ ~15 GB per 1M metrics/day
└─ Adjust for storage budget

Grafana (real-time display)
├─ Queries recent Prometheus data
├─ Historical data from time-series DB
└─ Adjust dashboard time range
```
