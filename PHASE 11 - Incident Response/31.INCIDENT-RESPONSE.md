## 31.1 Incident Response Framework (NIST IR Cycle)

### Four Phases of Incident Response

```
PHASE 1: PREPARATION
├─ Tools and resources ready
├─ Procedures documented
├─ Team trained
├─ Communications plan established
└─ Forensics capabilities in place

PHASE 2: DETECTION & ANALYSIS
├─ Monitor for suspicious activity
├─ Identify security incidents
├─ Classify severity
├─ Determine scope
└─ Activate incident response team

PHASE 3: CONTAINMENT, ERADICATION, RECOVERY
├─ SHORT-TERM CONTAINMENT
│  ├─ Isolate affected systems
│  └─ Prevent further damage
├─ LONG-TERM CONTAINMENT
│  ├─ Apply patches/configs
│  └─ Monitor for re-infection
├─ ERADICATION
│  ├─ Remove malware
│  ├─ Close vulnerability
│  └─ Verify removal
└─ RECOVERY
   ├─ Restore from clean backups
   ├─ Rebuild systems
   └─ Return to operations

PHASE 4: POST-INCIDENT ACTIVITY
├─ Conduct root cause analysis
├─ Document learnings
├─ Update procedures
├─ Implement preventive controls
├─ Notify stakeholders
└─ Review and improve IR process
```

## 31.2 Detection: Identifying Incidents

### Indicators of Compromise (IOCs)

```
NETWORK-LEVEL IOCs:
├─ Suspicious outbound connections
├─ Reverse shell connections
├─ Data exfiltration traffic
├─ C&C (Command & Control) communication
├─ DNS tunneling
├─ SSL/TLS handshake anomalies
└─ Unusual protocol usage

HOST-LEVEL IOCs:
├─ Unexpected processes running
├─ New/modified SUID binaries
├─ Rootkit signatures
├─ Suspicious startup entries
├─ Unauthorized user accounts
├─ Backdoor listeners
└─ Modified system files

APPLICATION-LEVEL IOCs:
├─ SQL injection attempts
├─ Path traversal attacks
├─ Command injection
├─ XXE (XML External Entity)
├─ Deserialization attacks
├─ Unusual error rates
└─ Slow/hanging responses

LOG-BASED IOCs:
├─ Multiple failed login attempts
├─ Privilege escalation attempts
├─ Access to sensitive files
├─ Unusual command execution
├─ Policy violation alerts
└─ Firewall blocks
```

### Detection Tools & Queries

```bash
# ELK/Elasticsearch incident detection
# Query: Multiple failed logins from single IP
GET logs-*/_search
{
  "query": {
    "bool": {
      "must": [
        { "term": { "event.type": "authentication:failure" } },
        { "range": { "@timestamp": { "gte": "now-24h" } } }
      ]
    }
  },
  "aggs": {
    "by_src_ip": {
      "terms": { "field": "source.ip", "size": 100 },
      "aggs": {
        "failure_count": { "value_count": { "field": "event.action" } }
      }
    }
  }
}

# Splunk query: Detect privilege escalation
index=main (sudo OR su) group=root 
| stats count by user, src_ip 
| where count > 3

# Wazuh rule: Detect suspicious process execution
rule_id: 80001
level: 7
description: "Suspicious process execution from /tmp"
match: /exec.*\/tmp\/

# Prometheus query: Detect resource exhaustion
increase(process_cpu_seconds_total[5m]) > 100
or
increase(process_resident_memory_bytes[5m]) > 1000000000

# Network detection (tcpdump): Detect potential exfiltration
tcpdump -i eth0 'tcp[tcpflags] & tcp-ack != 0' 
| awk '{print $3}' 
| cut -d: -f1 
| sort | uniq -c 
| awk '$1 > 10000 {print}'  # More than 10,000 packets
```

## 31.3 Evidence Preservation & Forensics

### Digital Forensics Checklist

```bash
#!/bin/bash
# forensics-collection.sh - Collect evidence from compromised system

EVIDENCE_DIR="/mnt/forensics/$(date +%Y%m%d-%H%M%S)"
mkdir -p "$EVIDENCE_DIR"

echo "=== Digital Forensics Evidence Collection ==="
echo "Target: $HOSTNAME"
echo "Time: $(date)"
echo "Collector: $(whoami)"
echo ""

# 1. CAPTURE VOLATILE DATA (Memory, processes, network)
echo "[1/10] Capturing memory..."
dd if=/dev/mem of="$EVIDENCE_DIR/memory.dd" bs=1M 2>/dev/null
# or use: sudo tar czf "$EVIDENCE_DIR/proc.tar.gz" /proc

# 2. RUNNING PROCESSES
echo "[2/10] Capturing processes..."
ps auxww > "$EVIDENCE_DIR/ps-auxww.txt"
pstree -ap > "$EVIDENCE_DIR/pstree.txt"
lsof -i > "$EVIDENCE_DIR/lsof-network.txt"
lsof > "$EVIDENCE_DIR/lsof-all.txt"

# 3. NETWORK STATE
echo "[3/10] Capturing network state..."
netstat -tulpn > "$EVIDENCE_DIR/netstat.txt"
ss -tunap > "$EVIDENCE_DIR/ss.txt"
ip route show > "$EVIDENCE_DIR/ip-route.txt"
ip link show > "$EVIDENCE_DIR/ip-link.txt"
iptables -L -n > "$EVIDENCE_DIR/iptables.txt"

# 4. SYSTEM CONFIGURATION
echo "[4/10] Capturing system configuration..."
uname -a > "$EVIDENCE_DIR/uname.txt"
hostnamectl > "$EVIDENCE_DIR/hostname.txt"
timedatectl > "$EVIDENCE_DIR/time.txt"
systemctl list-units > "$EVIDENCE_DIR/systemctl.txt"

# 5. USER & GROUP INFORMATION
echo "[5/10] Capturing user/group info..."
cat /etc/passwd > "$EVIDENCE_DIR/passwd"
cat /etc/shadow > "$EVIDENCE_DIR/shadow"  # If root
cat /etc/group > "$EVIDENCE_DIR/group"
cat /etc/sudoers > "$EVIDENCE_DIR/sudoers"
lastlog > "$EVIDENCE_DIR/lastlog.txt"
last > "$EVIDENCE_DIR/last.txt"
w > "$EVIDENCE_DIR/w.txt"

# 6. MOUNTED FILESYSTEMS & MOUNTS
echo "[6/10] Capturing filesystem info..."
mount > "$EVIDENCE_DIR/mount.txt"
df -h > "$EVIDENCE_DIR/df-h.txt"
lsblk > "$EVIDENCE_DIR/lsblk.txt"

# 7. KERNEL MODULES
echo "[7/10] Capturing kernel modules..."
lsmod > "$EVIDENCE_DIR/lsmod.txt"
cat /proc/modules > "$EVIDENCE_DIR/proc-modules.txt"

# 8. AUDIT LOGS
echo "[8/10] Capturing audit logs..."
cp /var/log/audit/audit.log "$EVIDENCE_DIR/"
ausearch -ts recent > "$EVIDENCE_DIR/ausearch-recent.txt"

# 9. SYSTEM LOGS
echo "[9/10] Capturing system logs..."
tar czf "$EVIDENCE_DIR/var-log.tar.gz" /var/log/
journalctl --no-pager > "$EVIDENCE_DIR/journalctl.txt"

# 10. FILESYSTEM SNAPSHOT
echo "[10/10] Creating filesystem snapshot..."
tar czf "$EVIDENCE_DIR/filesystem.tar.gz" \
  --exclude=/proc \
  --exclude=/sys \
  --exclude=/dev \
  --exclude=/mnt \
  --exclude=/tmp \
  /

# MAKE EVIDENCE IMMUTABLE
echo ""
echo "Making evidence immutable..."
chattr -R +i "$EVIDENCE_DIR"
chmod -R 000 "$EVIDENCE_DIR"

echo ""
echo "Evidence collection complete: $EVIDENCE_DIR"
echo "Total size: $(du -sh $EVIDENCE_DIR)"

# CHAIN OF CUSTODY
cat > "$EVIDENCE_DIR/CHAIN-OF-CUSTODY.txt" << EOF
CHAIN OF CUSTODY LOG

Date/Time: $(date)
Incident: [INCIDENT ID]
Collector: $(whoami)
System: $HOSTNAME
IP Address: $(hostname -I)

Evidence Location: $EVIDENCE_DIR
Collection Method: Digital Forensics Automated Script
MD5 Hash: $(find $EVIDENCE_DIR -type f -exec md5sum {} \;)

Transferred By: 
Received By:
Date/Time:

[Continue for each person handling evidence]
EOF

echo "Chain of custody created."
```

## 31.4 Attack Timeline Reconstruction

### Timeline Analysis Procedure

```bash
#!/bin/bash
# reconstruct-timeline.sh - Build attack timeline from logs

TIMELINE_FILE="attack-timeline-$(date +%Y%m%d).txt"

echo "=== INCIDENT TIMELINE RECONSTRUCTION ===" > "$TIMELINE_FILE"
echo "Date: $(date)" >> "$TIMELINE_FILE"
echo "" >> "$TIMELINE_FILE"

# Merge and sort all relevant logs by timestamp
echo "Analyzing audit logs, system logs, application logs..."

# Combine logs with timestamps
(
  grep -r "authentication\|login\|ssh\|password" /var/log/auth.log 2>/dev/null
  grep -r "sudo\|privilege" /var/log/audit/audit.log 2>/dev/null
  grep -r "error\|failed\|denied" /var/log/syslog 2>/dev/null
  grep -r "alert\|attack\|malware" /var/log/syslog 2>/dev/null
) | sort -k1,2 >> "$TIMELINE_FILE"

# Analyze Kubernetes events
kubectl get events -A --sort-by='.lastTimestamp' >> "$TIMELINE_FILE" 2>/dev/null

# Create summary
echo "" >> "$TIMELINE_FILE"
echo "=== SUMMARY ===" >> "$TIMELINE_FILE"
echo "First indicator of compromise:" >> "$TIMELINE_FILE"
head -1 "$TIMELINE_FILE" >> "$TIMELINE_FILE"

echo "" >> "$TIMELINE_FILE"
echo "Attack progression:" >> "$TIMELINE_FILE"
grep -E "14:23|14:25|14:30|14:35|14:40" "$TIMELINE_FILE" >> "$TIMELINE_FILE"

echo "" >> "$TIMELINE_FILE"
echo "Recovery actions:" >> "$TIMELINE_FILE"
grep -E "killed|removed|blocked|patched" "$TIMELINE_FILE" >> "$TIMELINE_FILE"

# Calculate attack duration
ATTACK_START=$(grep -oE "^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}" "$TIMELINE_FILE" | head -1)
ATTACK_END=$(grep -oE "^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}" "$TIMELINE_FILE" | tail -1)

echo "" >> "$TIMELINE_FILE"
echo "Attack Start: $ATTACK_START" >> "$TIMELINE_FILE"
echo "Attack End: $ATTACK_END" >> "$TIMELINE_FILE"

cat "$TIMELINE_FILE"
```

## 31.5 Incident Response Playbooks

### SQL Injection Attack Playbook

```
PLAYBOOK: SQL INJECTION ATTACK

SEVERITY: High (if database accessed)

INDICATORS:
├─ Unusual SQL error messages in logs
├─ Large queries with "UNION SELECT"
├─ Database activity at odd hours
└─ Data exfiltration detected

IMMEDIATE ACTIONS (0-30 min):
├─ [ ] Activate incident response team
├─ [ ] Notify database administrator
├─ [ ] Isolate affected web server
├─ [ ] Preserve logs and evidence
├─ [ ] Activate WAF rules to block SQLi patterns
└─ [ ] Begin timeline reconstruction

INVESTIGATION (30 min-2 hours):
├─ [ ] Identify source IP(s) of attacks
├─ [ ] Determine which tables accessed
├─ [ ] Check data access logs
├─ [ ] Review application error logs
├─ [ ] Identify vulnerable endpoint
└─ [ ] Scope of data compromise

CONTAINMENT (2-6 hours):
├─ [ ] Apply input validation fix
├─ [ ] Deploy parameterized queries
├─ [ ] Enable SQL query logging
├─ [ ] Update WAF rules
├─ [ ] Patch application
└─ [ ] Redeploy to production

RECOVERY (6-24 hours):
├─ [ ] Verify fix effectiveness
├─ [ ] Rotate database passwords
├─ [ ] Reset database credentials
├─ [ ] Enable enhanced logging
├─ [ ] Restore from clean backup if needed
└─ [ ] Verify data integrity

POST-INCIDENT (24-48 hours):
├─ [ ] Complete incident report
├─ [ ] Conduct post-mortem
├─ [ ] Update security procedures
├─ [ ] Implement automated detection
├─ [ ] Schedule security training
└─ [ ] Notify affected users
```

## 31.6 Chapter Summary

Incident Response Maturity:

```
LEVEL 1: Reactive
├─ No preparation
├─ Ad-hoc response
├─ No procedures
└─ Recovery takes weeks

LEVEL 2: Planned
├─ Basic procedures
├─ Response team identified
├─ Some tooling
└─ Recovery takes days

LEVEL 3: Managed
├─ Documented procedures
├─ Regular training
├─ Automated detection
└─ Recovery takes hours

LEVEL 4: Optimized
├─ Advanced playbooks
├─ Continuous monitoring
├─ Automation
└─ Recovery takes minutes
```
