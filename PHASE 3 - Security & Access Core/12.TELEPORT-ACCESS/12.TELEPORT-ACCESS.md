## 12.1 What is Zero Trust Access?

### Traditional SSH Model (Trust-Based)

```
User has private key → SSH directly to server → Shell
✅ Fast
❌ Hard to audit
❌ No session recording
❌ User has permanent access (hard to revoke)
❌ Compromised key = full access
```

### Teleport Model (Zero Trust)

```
User authenticates → Teleport Auth verifies → Issues short-lived cert
→ User connects through Teleport Proxy → Proxy records session
→ Connection to server via Teleport Agent → Shell

✅ Every access authenticated
✅ Session recording
✅ Fine-grained RBAC
✅ Short-lived certificates (automatic expiration)
✅ Revocation is instant
✅ Complete audit trail
```

🏗️ **Analogy:** Traditional SSH is like a building with permanent key cards. Teleport is like a building with a security guard who:

1. Checks your ID (authentication)
2. Checks if you're authorized to visit a floor (RBAC)
3. Escorts you to the elevator (proxy)
4. Records your visit on camera (session recording)
5. Access expires at end of shift (short-lived certs)

## 12.3 Installation

### Step 1 — Install Teleport

Log into `sec-vault-01` (where Vault is running):

```bash
$ ssh sec-vault-01
```

Download and install Teleport:

```bash
# Download Teleport
vm# cd /tmp
vm# wget https://cdn.teleport.dev/teleport-v14.0.0-linux-amd64-bin.tar.gz
vm# tar -xzf teleport-v14.0.0-linux-amd64-bin.tar.gz
vm# sudo mv teleport /usr/local/bin/

# Verify installation
vm# teleport version
```

```
# Expected output:
→ Teleport v14.0.0
```

### Step 2 — Create Teleport User and Directories

```bash
# Create teleport system user
vm# sudo useradd --system --home /var/lib/teleport --shell /usr/sbin/nologin teleport

# Create directories
vm# sudo mkdir -p /var/lib/teleport /var/log/teleport /etc/teleport
vm# sudo chown -R teleport:teleport /var/lib/teleport /var/log/teleport
vm# sudo chown root:teleport /etc/teleport
vm# sudo chmod 750 /etc/teleport
```

### Step 3 — Generate TLS Certificates

Teleport needs TLS for communication:

```bash
# Generate self-signed certificate (or use Vault-issued)
vm# sudo openssl req -x509 \
    -newkey rsa:2048 \
    -keyout /etc/teleport/teleport.key \
    -out /etc/teleport/teleport.crt \
    -days 1825 \
    -nodes \
    -subj "/CN=vault.devsecops.com/O=DevSecOps Lab/C=US"

vm# sudo chown teleport:teleport /etc/teleport/teleport.*
vm# sudo chmod 600 /etc/teleport/teleport.*
```

## 12.4 Configuration

Create Teleport configuration file:

```bash
vm# sudo tee /etc/teleport/teleport.yaml > /dev/null << 'EOF'
#
# Teleport Configuration
# Zero Trust Access Platform
#

version: v3

teleport:
  nodename: sec-vault-01
  data_dir: /var/lib/teleport
  log:
    output: /var/log/teleport/teleport.log
    severity: INFO
    format: json

  # TLS certificates
  https_key_file: /etc/teleport/teleport.key
  https_cert_file: /etc/teleport/teleport.crt

  # Cluster settings
  auth_token: /var/lib/teleport/token
  ca_pin: ""  # Set after initial setup

  # Connection limits
  connection_limits:
    max_connections: 1000
    max_users: 100

# Auth Service: Issues certificates, verifies credentials
auth_service:
  enabled: yes
  cluster_name: devsecops
  listen_addr: 0.0.0.0:3025
  
  # Token TTL (how long a session lasts)
  token_ttl: 8760h  # 1 year for initial setup; use shorter in production
  
  # Session recording
  session_recording: all  # Record all sessions
  
  # OIDC authentication
  oidc_connectors:
    - name: authentik
      client_id: teleport-client-id
      client_secret: teleport-client-secret
      redirect_url: https://vault.devsecops.com:3080/v1/webapi/oidc/callback
      issuer_url: http://sec-idm-01:9000/application/o/teleport/
      scopes: [openid, profile, email, offline_access]
      claims_to_roles:
        - claim: groups
          value: devops
          roles:
            - devops
        - claim: groups
          value: admin
          roles:
            - admin
        - claim: groups
          value: developers
          roles:
            - developers

# Proxy Service: Entry point for clients
proxy_service:
  enabled: yes
  listen_addr: 0.0.0.0:3023
  web_listen_addr: 0.0.0.0:3080
  
  # Public address (what clients connect to)
  public_addr: vault.devsecops.com:3023
  
  # Kubernetes proxy (for kubectl access)
  kube_listen_addr: 0.0.0.0:3026

# SSH Service: Allows SSH access
ssh_service:
  enabled: yes
  listen_addr: 0.0.0.0:3022
  
  # Hostnames this server accepts
  labels:
    env: lab
    service: vault

EOF

vm# sudo chown teleport:teleport /etc/teleport/teleport.yaml
vm# sudo chmod 600 /etc/teleport/teleport.yaml
```

## 12.5 Create Systemd Service

```bash
vm# sudo tee /etc/systemd/system/teleport.service > /dev/null << 'EOF'
[Unit]
Description=Teleport Zero Trust Access Platform
Documentation=https://goteleport.com/docs/
After=network.target
Wants=network-online.target

[Service]
Type=notify
User=teleport
Group=teleport

ExecStart=/usr/local/bin/teleport start --config=/etc/teleport/teleport.yaml
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=5

StandardOutput=journal
StandardError=journal
SyslogIdentifier=teleport

[Install]
WantedBy=multi-user.target

EOF

vm# sudo systemctl daemon-reload
vm# sudo systemctl enable teleport
```

## 12.7 Define Roles

Roles control what users can do. Create RBAC rules:

```bash
# Create admin role (full access)
vm# cat > /tmp/admin-role.yaml << 'EOF'
kind: role
version: v5
metadata:
  name: admin
spec:
  options:
    forward_agent: yes
    max_session_ttl: 24h
    client_idle_timeout: 30m
    disconnect_expired_cert: yes
  allow:
    logins: [root, ubuntu, teleport]
    node_labels:
      env: [lab]
    kubernetes_groups: [system:masters]
    db_users: [admin, root]
    db_names: [postgres, mysql]
    aws_role_arns: ["*"]
  deny:
    # Admin cannot access certain sensitive paths
    node_labels:
      env: [production]

EOF

# Apply role
vm# tctl create /tmp/admin-role.yaml
```

```bash
# Create devops role (limited access)
vm# cat > /tmp/devops-role.yaml << 'EOF'
kind: role
version: v5
metadata:
  name: devops
spec:
  options:
    forward_agent: yes
    max_session_ttl: 8h
    client_idle_timeout: 15m
    disconnect_expired_cert: yes
  allow:
    logins: [ubuntu, devops]
    node_labels:
      env: [lab]
      service: [*]
    kubernetes_groups: [system:view]
    db_users: [devops]
    db_names: [postgres]
  deny:
    # Cannot access auth nodes
    node_labels:
      service: [auth]

EOF

vm# tctl create /tmp/devops-role.yaml
```

```bash
# Create developers role (minimal access)
vm# cat > /tmp/developers-role.yaml << 'EOF'
kind: role
version: v5
metadata:
  name: developers
spec:
  options:
    max_session_ttl: 4h
    client_idle_timeout: 15m
  allow:
    logins: [ubuntu]
    node_labels:
      env: [lab]
      service: [app]  # Only access app servers
    kubernetes_groups: [system:view]
  deny: {}

EOF

vm# tctl create /tmp/developers-role.yaml
```

## 12.8 Integrate with Authentik (OIDC)

Configure Authentik to issue tokens that Teleport accepts:

### In Authentik Admin Console:

1. **Applications → Create Application**
    
    - Name: Teleport
    - Slug: teleport
    - Provider: OAuth2/OIDC (create new)
2. **OAuth2 Provider Settings:**
    
    - Client ID: `teleport-client-id` (match teleport.yaml)
    - Client Secret: `teleport-client-secret`
    - Redirect URIs: `https://vault.devsecops.com:3080/v1/webapi/oidc/callback`
    - Scopes: openid, profile, email, offline_access
3. **Groups:**
    
    - Map LDAP groups (devops, admin, developers) to Authentik groups
    - These groups appear in `claims_to_roles` mapping

## 12.9 Register Nodes with Teleport

Nodes (servers) must register with Teleport before accepting connections.

### Install Teleport Agent on Each Node

For each VM that should be accessible via Teleport:

```bash
# Install Teleport agent on target server (e.g., sec-idm-01)
$ ssh sec-idm-01 'cd /tmp && \
    wget https://cdn.teleport.dev/teleport-v14.0.0-linux-amd64-bin.tar.gz && \
    tar -xzf teleport-v14.0.0-linux-amd64-bin.tar.gz && \
    sudo mv teleport /usr/local/bin/'

# Generate join token
vm# ssh sec-vault-01 'tctl nodes add --roles=node --ttl=1h' > /tmp/teleport_token

# Register node
$ ssh sec-idm-01 'sudo teleport node start \
    --auth-server=vault.devsecops.com:3025 \
    --token=$(cat /tmp/teleport_token) \
    --labels=env=lab,service=idm'
```

### Configure Agent Service

Create systemd service for agent on each node:

```bash
# On target node (sec-idm-01)
$ ssh sec-idm-01 'sudo tee /etc/teleport-node.yaml' << 'EOF'
version: v3

teleport:
  nodename: sec-idm-01
  auth_token: /var/lib/teleport/join_token
  ca_pin: ""
  auth_servers:
    - vault.devsecops.com:3025

ssh_service:
  enabled: yes
  listen_addr: 0.0.0.0:3022
  labels:
    env: lab
    service: idm

EOF
```

Create service file:

```bash
$ ssh sec-idm-01 'sudo tee /etc/systemd/system/teleport-node.service' << 'EOF'
[Unit]
Description=Teleport Node Agent
After=network.target

[Service]
User=root
ExecStart=/usr/local/bin/teleport node start --config=/etc/teleport-node.yaml
Restart=always

[Install]
WantedBy=multi-user.target

EOF

# Start agent
$ ssh sec-idm-01 'sudo systemctl daemon-reload && \
    sudo systemctl enable teleport-node && \
    sudo systemctl start teleport-node'
```

## 12.10 Client Access via Teleport

Users connect using `tsh` (Teleport Shell) client:

### Step 1 — Install tsh Client (on your host)

```bash
# Download tsh
$ wget https://cdn.teleport.dev/teleport-v14.0.0-linux-amd64-bin.tar.gz
$ tar -xzf teleport-v14.0.0-linux-amd64-bin.tar.gz
$ sudo mv teleport /usr/local/bin/
$ tsh version
```

### Step 2 — Login to Teleport

```bash
# Login (redirects to Authentik for OIDC)
$ tsh login --proxy=vault.devsecops.com:3023
```

This opens your browser to Authentik. Log in with your LDAP credentials. Authentik redirects back to Teleport, which issues a short-lived certificate.

```bash
# Verify login
$ tsh status
```

## 12.13 Audit Logging

All access is logged in Teleport's audit log:

```bash
# View audit events
vm# tctl audit get --from=2025-01-01 --to=2025-12-31 | head -20
```

Each event shows:

- **User:** Who accessed the system (john, alice, bob)
- **Timestamp:** When (2025-01-15 14:30:45)
- **Event:** What (user_login, session_start, session_command, session_end)
- **Resource:** What was accessed (node: sec-idm-01)
- **Result:** Success or failure
- **Session ID:** Link to session recording

## 12.15 Troubleshooting

### Problem: "Connection refused" on port 3023

Teleport not listening:

```bash
vm# netstat -tulnp | grep 3023
# Should show: LISTEN 0.0.0.0:3023
```

Check service status:

```bash
vm# sudo systemctl status teleport
vm# sudo journalctl -xeu teleport -n 50
```

### Problem: OIDC login fails

Authentik configuration mismatch:

```bash
# Verify Teleport config
vm# grep -A10 oidc_connectors /etc/teleport/teleport.yaml

# Verify Authentik app
# Applications → Teleport → Check redirect URI matches
# https://vault.devsecops.com:3080/v1/webapi/oidc/callback
```

### Problem: Node won't register

Node can't reach auth server:

```bash
# On node, verify connectivity:
$ ssh sec-idm-01 'nc -zv vault.devsecops.com 3025'
# Should show: succeeded

# Check node token
vm# tctl tokens ls
```

### Problem: Session recording not working

Verify recording is enabled:

```bash
vm# grep "session_recording" /etc/teleport/teleport.yaml
# Should show: session_recording: all
```

## 12.16 Validation Script — Chapter 12

```bash
#!/bin/bash
# ~/lab/scripts/validate-chapter-12.sh

set -euo pipefail

TELEPORT_IP="10.0.2.13"
PASS=0
FAIL=0

echo "============================================="
echo " Chapter 12 Validation — Teleport Access    "
echo "============================================="

echo ""
echo "--- Teleport Service ---"

result=$(ssh sec-vault-01 'systemctl is-active teleport' 2>/dev/null || echo "error")
if [ "$result" = "active" ]; then
    echo "  ✅ PASS: Teleport service is active"
    ((PASS++))
else
    echo "  ❌ FAIL: Teleport service is not active"
    ((FAIL++))
fi

echo ""
echo "--- Network Listening ---"

for port in 3023 3025 3080; do
    if nc -z $TELEPORT_IP $port 2>/dev/null; then
        echo "  ✅ PASS: Teleport listening on port $port"
        ((PASS++))
    else
        echo "  ❌ FAIL: Teleport not listening on port $port"
        ((FAIL++))
    fi
done

echo ""
echo "--- Web UI Access ---"

if curl -s -k https://$TELEPORT_IP:3080/ 2>/dev/null | grep -q "teleport"; then
    echo "  ✅ PASS: Web UI is accessible"
    ((PASS++))
else
    echo "  ⚠️  WARNING: Web UI may not be fully loaded"
    ((PASS++))
fi

echo ""
echo "--- Nodes Registered ---"

nodes=$(ssh sec-vault-01 'tctl nodes ls 2>/dev/null | wc -l' || echo "0")
if [ "$nodes" -gt 0 ]; then
    echo "  ✅ PASS: Nodes registered with Teleport ($nodes)"
    ((PASS++))
else
    echo "  ⚠️  WARNING: No nodes registered yet"
    ((PASS++))
fi

echo ""
echo "--- OIDC Configuration ---"

if ssh sec-vault-01 'grep -q "oidc_connectors" /etc/teleport/teleport.yaml' 2>/dev/null; then
    echo "  ✅ PASS: OIDC authentication configured"
    ((PASS++))
else
    echo "  ⚠️  WARNING: OIDC not configured"
    ((PASS++))
fi

echo ""
echo "--- Results ---"
echo "  Passed: ${PASS}"
echo "  Failed: ${FAIL}"

if [ "$FAIL" -eq 0 ]; then
    echo ""
    echo "🎉 Teleport is operational!"
    echo "   Connect with: tsh login --proxy=vault.devsecops.com:3023"
else
    echo ""
    echo "⚠️  ${FAIL} check(s) failed."
    exit 1
fi

```
