## 24.1 Why Helm?

Kubernetes YAML can get repetitive:

```yaml
# Without Helm: Too much duplication
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp-prod
  labels:
    app: myapp
    env: production
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
  template:
    ...
---
apiVersion: v1
kind: Service
metadata:
  name: myapp-prod-service
spec:
  selector:
    app: myapp
  ...
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: myapp-prod-config
data:
  database_host: postgres-prod.default.svc
  ...
```

Helm solves this with templates:

```yaml
# With Helm: Reusable templates
# values.yaml:
environment: production
replicas: 3
database_host: postgres-prod.default.svc

# templates/deployment.yaml:
{{ .Values.environment }}
{{ .Values.replicas }}
{{ .Values.database_host }}

# Result: One chart, infinite configurations
```

## 24.2 Helm Chart Structure

### Chart Directory Layout

```
myapp-chart/
├── Chart.yaml           # Chart metadata
├── values.yaml          # Default values
├── templates/
│   ├── deployment.yaml  # Kubernetes resources
│   ├── service.yaml
│   ├── configmap.yaml
│   ├── secret.yaml
│   └── _helpers.tpl     # Template helpers
├── charts/              # Subchart dependencies
└── README.md            # Documentation
```

### Chart.yaml

```yaml
apiVersion: v2
name: myapp
description: A Helm chart for MyApp
type: application
version: 1.0.0
appVersion: "2.1.0"
keywords:
  - myapp
  - application
home: https://myapp.dev
sources:
  - https://github.com/mycompany/myapp
maintainers:
  - name: John Doe
    email: john@mycompany.com
```

### values.yaml (Default Configuration)

```yaml
# Default values
replicaCount: 3

image:
  repository: harbor.devsecops.com/myapp/myapp
  pullPolicy: IfNotPresent
  tag: "1.0.0"

imagePullSecrets:
  - name: harbor-secret

nameOverride: ""
fullnameOverride: ""

service:
  type: LoadBalancer
  port: 80
  targetPort: 8080

ingress:
  enabled: true
  className: "nginx"
  annotations:
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
  hosts:
    - host: myapp.devsecops.com
      paths:
        - path: /
          pathType: Prefix

resources:
  limits:
    cpu: 500m
    memory: 512Mi
  requests:
    cpu: 250m
    memory: 256Mi

autoscaling:
  enabled: true
  minReplicas: 3
  maxReplicas: 10
  targetCPUUtilizationPercentage: 80

database:
  host: postgresql.default.svc.cluster.local
  port: 5432
  name: myapp
  username: app_user
```

## 24.3 Templating

### Deployment Template

```yaml
# templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "myapp.fullname" . }}
  labels:
    {{- include "myapp.labels" . | nindent 4 }}
spec:
  {{- if not .Values.autoscaling.enabled }}
  replicas: {{ .Values.replicaCount }}
  {{- end }}
  selector:
    matchLabels:
      {{- include "myapp.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "myapp.selectorLabels" . | nindent 8 }}
    spec:
      {{- with .Values.imagePullSecrets }}
      imagePullSecrets:
        {{- toYaml . | nindent 8 }}
      {{- end }}
      containers:
      - name: {{ .Chart.Name }}
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag }}"
        imagePullPolicy: {{ .Values.image.pullPolicy }}
        ports:
        - name: http
          containerPort: {{ .Values.service.targetPort }}
          protocol: TCP
        env:
        - name: DATABASE_HOST
          value: {{ .Values.database.host }}
        - name: DATABASE_PORT
          value: "{{ .Values.database.port }}"
        - name: DATABASE_NAME
          value: {{ .Values.database.name }}
        resources:
          {{- toYaml .Values.resources | nindent 12 }}
```

### Helpers Template

```yaml
# templates/_helpers.tpl
{{- define "myapp.name" -}}
{{- default .Chart.Name .Values.nameOverride | trunc 63 }}
{{- end }}

{{- define "myapp.fullname" -}}
{{- printf "%s-%s" .Release.Name (include "myapp.name" .) | trunc 63 }}
{{- end }}

{{- define "myapp.labels" -}}
helm.sh/chart: {{ include "myapp.chart" . }}
{{ include "myapp.selectorLabels" . }}
{{- end }}

{{- define "myapp.selectorLabels" -}}
app.kubernetes.io/name: {{ include "myapp.name" . }}
app.kubernetes.io/instance: {{ .Release.Name }}
{{- end }}
```

## 24.4 Installing & Managing Releases

### Install Chart

```bash
# Install with default values
helm install myapp ./myapp-chart

# Install with custom values
helm install myapp ./myapp-chart \
  --values custom-values.yaml

# Install with inline value overrides
helm install myapp ./myapp-chart \
  --set replicaCount=5 \
  --set image.tag=2.0.0 \
  --set ingress.enabled=true

# Install to specific namespace
helm install myapp ./myapp-chart \
  -n myapp-production \
  --create-namespace
```

### Upgrade Release

```bash
# Upgrade to new version
helm upgrade myapp ./myapp-chart

# Upgrade with new values
helm upgrade myapp ./myapp-chart \
  --set image.tag=2.1.0

# Upgrade with --atomic (rollback on failure)
helm upgrade --atomic myapp ./myapp-chart
```

### Rollback Release

```bash
# See release history
helm history myapp

# Rollback to previous version
helm rollback myapp

# Rollback to specific revision
helm rollback myapp 2
```

### Uninstall Release

```bash
# Remove release
helm uninstall myapp

# Delete namespace too
helm uninstall myapp -n myapp-production
kubectl delete namespace myapp-production
```

## 24.5 Public Charts (Artifact Hub)

Use pre-built charts for common applications:

```bash
# Add Helm repositories
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo add stable https://charts.helm.sh/stable
helm repo add jetstack https://charts.jetstack.io
helm repo update

# Search for charts
helm search repo prometheus

# Install from public repo
helm install prometheus prometheus-community/kube-prometheus-stack \
  -n monitoring \
  --create-namespace

# Install cert-manager (for HTTPS)
helm install cert-manager jetstack/cert-manager \
  -n cert-manager \
  --create-namespace \
  --set installCRDs=true
```

## 24.6 Chart Dependencies

### Chart.yaml with Dependencies

```yaml
apiVersion: v2
name: myapp-stack
description: MyApp with PostgreSQL and Redis

dependencies:
  - name: postgresql
    version: "11.x.x"
    repository: https://charts.bitnami.com/bitnami
    condition: postgresql.enabled
    
  - name: redis
    version: "17.x.x"
    repository: https://charts.bitnami.com/bitnami
    condition: redis.enabled
    
  - name: myapp
    version: "1.0.0"
    repository: file://../myapp-chart
```

### Update Dependencies

```bash
# Download dependency charts
helm dependency update

# Lists dependencies
helm dependency list
```

## 24.7 Values Overrides

### Production Values

```yaml
# values-prod.yaml
replicaCount: 5

image:
  tag: "2.1.0"
  pullPolicy: Always

resources:
  requests:
    cpu: 1000m
    memory: 1Gi
  limits:
    cpu: 2000m
    memory: 2Gi

autoscaling:
  enabled: true
  minReplicas: 5
  maxReplicas: 20
  targetCPUUtilizationPercentage: 70

postgresql:
  enabled: true
  primary:
    persistence:
      size: 100Gi
```

### Development Values

```yaml
# values-dev.yaml
replicaCount: 1

image:
  tag: "latest"
  pullPolicy: Always

resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: 500m
    memory: 512Mi

autoscaling:
  enabled: false

postgresql:
  enabled: true
  primary:
    persistence:
      size: 10Gi
```

### Deploy with Values

```bash
# Production
helm install myapp ./myapp-chart \
  -f values-prod.yaml \
  -n production

# Development
helm install myapp-dev ./myapp-chart \
  -f values-dev.yaml \
  -n development
```

## 24.8 Dry Run & Debugging

### Dry Run (Preview Changes)

```bash
# See what Helm will create
helm install myapp ./myapp-chart \
  --dry-run \
  --debug

# See rendered templates
helm template myapp ./myapp-chart
```

### Lint Chart

```bash
# Check chart for errors
helm lint ./myapp-chart

# Output:
→ [INFO] Chart.yaml: icon is missing
→ [WARNING] Chart.yaml: unsupported API version
→ [ERROR] values.yaml: invalid YAML
```

## 24.9 Integration with Phase 1-4

### Package CI/CD Pipeline Application

```yaml
# Chart for application built in Phase 4

name: devsecops-app

dependencies:
  - name: postgresql
    version: "11.x"
    repository: https://charts.bitnami.com/bitnami
    
image:
  repository: harbor.devsecops.com/devsecops/app
  tag: "1.0.0"

vault:
  address: https://vault.devsecops.com
  role: kubernetes
```

Deploy with Vault secrets:

```bash
helm install devsecops-app ./devsecops-app-chart \
  --set vault.address=https://vault.devsecops.com \
  --set vault.role=app-role \
  -n devsecops
```

## 24.10 Chapter Summary

|Feature|Purpose|Example|
|---|---|---|
|**Chart.yaml**|Metadata|Name, version, description|
|**values.yaml**|Default config|Replicas, image, resources|
|**Templates**|Kubernetes YAML|Deployment, Service|
|**Helm Install**|Deploy application|helm install myapp ./chart|
|**Helm Upgrade**|Update version|helm upgrade myapp ./chart|
|**Helm Rollback**|Revert to previous|helm rollback myapp|

💡 **Key Takeaway — Reusable, Manageable Applications:**

Before Helm:

- ❌ Complex YAML files
- ❌ Repetitive configuration
- ❌ Hard to share applications
- ❌ Manual version management

After Helm:

- ✅ Templated, DRY YAML
- ✅ Configurable with values
- ✅ Share charts on Artifact Hub
- ✅ Automatic release management
- ✅ One-command deployments
