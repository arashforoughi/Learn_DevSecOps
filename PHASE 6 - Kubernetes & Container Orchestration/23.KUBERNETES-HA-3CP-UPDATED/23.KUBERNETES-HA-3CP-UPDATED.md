## 🏗️ **HA ARCHITECTURE BENEFITS**

### **Quorum-Based Availability**

```
etcd Cluster (3 nodes):
├─ Quorum = 2 of 3
├─ Can lose 1 node and still function
├─ Leader election automatic
└─ Data replicated across all 3

API Server (3 instances):
├─ Any of 3 can serve requests
├─ Load balanced behind HAProxy VIP
├─ Health checks every 1 second
└─ Automatic failover on timeout

Scheduler (3 instances):
├─ Only leader schedules
├─ Automatic leader election
└─ Transparent to users
```

### **Failure Scenarios**

|Scenario|Result|
|---|---|
|1 CP down|✅ Cluster continues (2 replicas remain)|
|1 worker down|✅ Pods rescheduled to other workers|
|Network partition|✅ Majority partition survives|
|Load balancer down|⚠️ Direct CP IPs still work|

**RTO: < 5 seconds (automatic failover)**  
**RPO: 0 (etcd replicates synchronously)**

## 🔄 **CLUSTER INITIALIZATION FLOW**

### **Phase 1: Prepare Infrastructure**

```bash
# On HAProxy node (10.0.2.25 or existing edge node)
# Install load balancer
sudo apt-get install -y haproxy

# Configure VIP (10.0.2.25:6443) → {cp-01, cp-02, cp-03}
# Health checks on TCP:6443 every 1 second
```

### **Phase 2: Initialize First CP Node**

```bash
# k8s-cp-01 initializes the cluster
kubeadm init --config=kubeadm-config.yaml \
  --control-plane-endpoint="10.0.2.25:6443" \
  --upload-certs

# Saves root CA, etcd certs, and control-plane certs
# Outputs join token (valid for 24 hours)
```

### **Phase 3: Join CP-02 & CP-03**

```bash
# Each additional CP node joins with:
# --control-plane flag (not just worker)
# --certificate-key (enables mutual TLS auth)

kubeadm join 10.0.2.25:6443 \
  --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash> \
  --control-plane \
  --certificate-key <key>
```

### **Phase 4: Join Worker Nodes**

```bash
# Workers join without --control-plane flag
kubeadm join 10.0.2.25:6443 \
  --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>
```

### **Phase 5: Install CNI & Verification**

```bash
kubectl apply -f https://docs.projectcalico.org/manifests/calico.yaml

# All 5 nodes should show: STATUS = Ready
kubectl get nodes
```

## 🔐 **HA SPECIFIC SECURITY CONSIDERATIONS**

### **Stacked etcd (Integrated)**

```
Each CP node runs:
├─ kube-apiserver (port 6443)
├─ kube-scheduler (port 10259)
├─ kube-controller-manager (port 10257)
└─ etcd (port 2379)

Communication:
├─ CP-to-etcd: localhost (secure)
├─ CP-to-CP: mTLS (mutual certificate auth)
└─ Workers-to-API: mTLS (kubelet cert)
```

### **etcd Replication**

```
Write → CP-01 (leader) 
      → CP-02 (follower)
      → CP-03 (follower)
      
Only written to disk when quorum (2+1) ack
= Zero data loss on failure
```

## 🚨 **CRITICAL: Backup Procedure**

With multiple CP nodes, **etcd backup is CRITICAL**:

```bash
# Backup etcd from any CP node
sudo su -
export ETCDCTL_API=3
etcdctl --endpoints=127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /backup/etcd-backup-$(date +%Y%m%d-%H%M%S).db

# Keep backups off-cluster (S3, NFS, etc.)
```

## 📈 **SCALING WORKER NODES**

With 3 HA CP nodes, add workers easily:

```bash
# For each new worker node (k8s-worker-03, k8s-worker-04, etc.)
# IP: 10.0.2.25+ (increment as needed, max .254)

sudo kubeadm join 10.0.2.25:6443 \
  --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>

# New workers automatically join the cluster
# Pods can be scheduled on new workers immediately
```
