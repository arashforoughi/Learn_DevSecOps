# Chapter 23 — Kubernetes: HA 3-Node Control-Plane Cluster

## DevSecOps Lab Book — Phase 6: Container Orchestration

---

> **Chapter Goal**
> 
> Deploy a production-grade, highly-available Kubernetes cluster with **3 Control-Plane nodes** (HA etcd cluster) and 2 worker nodes. This is the enterprise-standard architecture with no single point of failure.
> 
> By the end of this chapter:
> 
> - 3 Control-Plane nodes with distributed etcd
> - 2 Worker nodes operational
> - Container networking (CNI - Calico)
> - Storage provisioning (PersistentVolumes)
> - RBAC configured
> - HA load balancing for API server
> - Monitoring integrated
> 
> **Architecture:** 3 Control-Planes (HA) → 2 Worker Nodes → Container Workloads
> 
> **Time estimate:** 6–7 hours.

## 23.1 Why HA Control-Plane?

### Single Control-Plane (❌ Not Production)

```
┌──────────────────────┐
│ k8s-master-01        │
│ - API Server DOWN    │
│ - etcd DOWN          │
│ - Scheduler DOWN     │
└──────────────────────┘
         ↓
  NO CLUSTER CONTROL
  - Can't schedule pods
  - Can't manage services
  - Cluster is DEAD
  
  RTO (Recovery Time): Unknown (manual recovery)
```

### HA 3-Node Control-Plane (✅ Production-Ready)

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ k8s-cp-01    │  │ k8s-cp-02    │  │ k8s-cp-03    │
│ CP + etcd    │  │ CP + etcd    │  │ CP + etcd    │
│ 10.0.2.20    │  │ 10.0.2.21    │  │ 10.0.2.22    │
└──────┬───────┘  └──────┬───────┘  └──────┬───────┘
       │                 │                 │
       └─────────────┬───┴─────────────┬───┘
                     │                 │
          ┌──────────▼─────────────────┘
          │
      ┌───▼──────────────┐
      │   VIP (Load Bal) │
      │   10.0.2.25      │
      │   (HAProxy)      │
      └─────────────────┘

Result:
✅ One CP node fails → Other 2 continue (quorum: 2/3)
✅ etcd replicates across all 3 nodes
✅ Load balancer routes to healthy CP
✅ RTO < 5 seconds (automatic failover)
```

## 23.3 Installation (kubeadm HA Setup)

### Prerequisites on ALL Nodes

```bash
# On all 5 nodes: k8s-cp-01, k8s-cp-02, k8s-cp-03, k8s-worker-01, k8s-worker-02

# 1. Install Docker
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# 2. Install kubeadm, kubelet, kubectl
curl -fsSL https://packages.cloud.google.com/apt/doc/apt-key.gpg | sudo apt-key add -
sudo apt-add-repository "deb http://apt.kubernetes.io/ kubernetes-xenial main"
sudo apt-get update
sudo apt-get install -y kubeadm kubelet kubectl

# 3. Disable swap (required for Kubernetes)
sudo swapoff -a
sudo sed -i '/swap/d' /etc/fstab

# 4. Enable IP forwarding
sudo sysctl -w net.ipv4.ip_forward=1
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf
```

### Step 1: Install HAProxy Load Balancer

First, we need a load balancer for the API server before initializing the cluster:

```bash
# On HAProxy VM (or dedicated LB VM at 10.0.2.25)
sudo apt-get install -y haproxy

# Configure /etc/haproxy/haproxy.cfg
cat >> /etc/haproxy/haproxy.cfg << 'EOF'

frontend kubernetes-api
  bind *:6443
  mode tcp
  default_backend kubernetes-cp-nodes

backend kubernetes-cp-nodes
  mode tcp
  balance roundrobin
  
  server cp-01 10.0.2.20:6443 check
  server cp-02 10.0.2.21:6443 check
  server cp-03 10.0.2.22:6443 check
EOF

sudo systemctl restart haproxy
```

### Step 2: Initialize First Control-Plane (k8s-cp-01)

```bash
# On k8s-cp-01 ONLY

# Create kubeadm config
cat > kubeadm-config.yaml << 'EOF'
apiVersion: kubeadm.k8s.io/v1beta3
kind: ClusterConfiguration
kubernetesVersion: v1.27.0
controlPlaneEndpoint: "10.0.2.25:6443"  # Load balancer VIP
etcd:
  local:
    dataDir: /var/lib/etcd
networking:
  podSubnet: "10.244.0.0/16"
  serviceSubnet: "10.96.0.0/12"
---
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
cgroupDriver: systemd
EOF

# Initialize control plane
sudo kubeadm init --config=kubeadm-config.yaml \
  --upload-certs

# This outputs the join command for other nodes (SAVE THIS!)
# You'll see: kubeadm join 10.0.2.25:6443 --token xxx --discovery-token-ca-cert-hash sha256:xxx

# Configure kubectl
mkdir -p $HOME/.kube
sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# Verify first node
kubectl get nodes
# Should show cp-01 as NotReady (waiting for CNI)
```

### Step 3: Join Second Control-Plane (k8s-cp-02)

```bash
# On k8s-cp-02

# Use the join command from step 2, with --control-plane flag
sudo kubeadm join 10.0.2.25:6443 \
  --token <TOKEN> \
  --discovery-token-ca-cert-hash sha256:<HASH> \
  --control-plane \
  --certificate-key <CERT_KEY>

# Verify
kubectl get nodes
# Should now show cp-01 and cp-02 (both NotReady)
```

### Step 4: Join Third Control-Plane (k8s-cp-03)

```bash
# Same as Step 3, run on k8s-cp-03

sudo kubeadm join 10.0.2.25:6443 \
  --token <TOKEN> \
  --discovery-token-ca-cert-hash sha256:<HASH> \
  --control-plane \
  --certificate-key <CERT_KEY>

# Verify all 3 CPs
kubectl get nodes
# Should show cp-01, cp-02, cp-03 (all NotReady until CNI)
```

### Step 5: Join Worker Nodes (k8s-worker-01, k8s-worker-02)

```bash
# On k8s-worker-01 and k8s-worker-02

# Use the join command from step 2 (WITHOUT --control-plane)
sudo kubeadm join 10.0.2.25:6443 \
  --token <TOKEN> \
  --discovery-token-ca-cert-hash sha256:<HASH>

# Verify all nodes
kubectl get nodes
# Should show: cp-01, cp-02, cp-03, worker-01, worker-02 (all NotReady)
```

### Step 6: Install CNI Plugin (Calico)

```bash
# Run on any control plane node

kubectl apply -f https://docs.projectcalico.org/manifests/calico.yaml

# Wait for CNI to deploy
kubectl wait --for=condition=Ready pod \
  -l k8s-app=calico-node \
  -n kube-system \
  --timeout=300s

# Verify all nodes are Ready
kubectl get nodes
# All should now show: STATUS = Ready
```

### Verify HA etcd Cluster

```bash
# Check etcd member status (from any CP node)
kubectl exec -it etcd-k8s-cp-01 -n kube-system -- \
  etcdctl --endpoints=127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  member list

# Output should show all 3 etcd members:
# member1: cp-01
# member2: cp-02
# member3: cp-03
```

## 23.4 Core Concepts

### Pods (Smallest Deployable Unit)

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
spec:
  containers:
  - name: nginx
    image: nginx:latest
    ports:
    - containerPort: 80
```

Deploy:

```bash
kubectl apply -f pod.yaml
kubectl get pods
kubectl logs nginx-pod
```

### Deployments (Declarative Updates)

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 3  # Keep 3 copies running
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.19
        resources:
          requests:
            memory: "64Mi"
            cpu: "250m"
          limits:
            memory: "128Mi"
            cpu: "500m"
```

Deploy:

```bash
kubectl apply -f deployment.yaml
kubectl get deployments
kubectl scale deployment nginx-deployment --replicas=5
kubectl set image deployment/nginx-deployment \
  nginx=nginx:1.20  # Rolling update
```

### Services (Expose Pods)

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  type: LoadBalancer  # or ClusterIP, NodePort
  selector:
    app: nginx
  ports:
  - protocol: TCP
    port: 80
    targetPort: 80
```

## 23.5 Storage Management

### PersistentVolumes & Claims

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: database-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 10Gi
  storageClassName: standard

---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: postgresql
spec:
  serviceName: postgresql
  replicas: 1
  selector:
    matchLabels:
      app: postgresql
  template:
    metadata:
      labels:
        app: postgresql
    spec:
      containers:
      - name: postgresql
        image: postgres:14
        volumeMounts:
        - name: database
          mountPath: /var/lib/postgresql/data
  volumeClaimTemplates:
  - metadata:
      name: database
    spec:
      accessModes: [ "ReadWriteOnce" ]
      resources:
        requests:
          storage: 50Gi
```

## 23.6 ConfigMaps & Secrets

### ConfigMaps (Non-sensitive Configuration)

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  database_host: "postgresql.default.svc.cluster.local"
  database_port: "5432"
  log_level: "info"
```

### Secrets (Sensitive Data)

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secrets
type: Opaque
data:
  database_password: cG9zdGdyZXM=  # base64 encoded
  api_key: c2VjcmV0LWtleQ==
```

Mount in pods:

```yaml
spec:
  containers:
  - name: app
    image: myapp:latest
    envFrom:
    - configMapRef:
        name: app-config
    - secretRef:
        name: app-secrets
```

## 23.7 RBAC (Role-Based Access Control)

### ServiceAccount & Roles

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: app-service-account

---
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: app-role
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "list", "watch"]
- apiGroups: [""]
  resources: ["configmaps"]
  verbs: ["get"]

---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: app-rolebinding
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: app-role
subjects:
- kind: ServiceAccount
  name: app-service-account
```

## 23.8 Monitoring & Logging

### Deploy Prometheus & Grafana

```bash
# Add Prometheus Helm repo
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

# Install Prometheus
helm install prometheus prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --create-namespace

# Access Grafana
kubectl port-forward -n monitoring svc/prometheus-grafana 3000:80
# Visit: http://localhost:3000 (admin/prom-operator)
```

### View Logs

```bash
# Pod logs
kubectl logs -f deployment/nginx-deployment

# Previous logs (if pod crashed)
kubectl logs --previous pod-name

# All logs from label
kubectl logs -l app=nginx
```

## 23.9 Integration with Phase 1-5

### Deploy from Harbor (Phase 4)

```bash
# Create secret for Harbor authentication
kubectl create secret docker-registry harbor-secret \
  --docker-server=harbor.devsecops.com \
  --docker-username=admin \
  --docker-password=HarborPassword \
  --docker-email=admin@devsecops.com

# Use in deployment
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  template:
    spec:
      imagePullSecrets:
      - name: harbor-secret
      containers:
      - name: app
        image: harbor.devsecops.com/myapp/myapp:latest
```

### Access Vault Secrets (Phase 3)

```bash
# Install Vault Kubernetes auth
# (enables pods to authenticate to Vault)

# Deploy with Vault integration
kubectl apply -f - << EOF
apiVersion: v1
kind: Pod
metadata:
  name: app-with-vault
spec:
  containers:
  - name: app
    image: myapp:latest
    env:
    - name: VAULT_ADDR
      value: "https://vault.devsecops.com"
    - name: VAULT_ROLE
      value: "app"
    volumeMounts:
    - name: vault-auth
      mountPath: /var/run/secrets/tokens
  volumes:
  - name: vault-auth
    projected:
      sources:
      - serviceAccountToken:
          audience: vault
          expirationSeconds: 3600
          path: vault
EOF
```

## 23.10 Chapter Summary

|Component|Purpose|Example|
|---|---|---|
|**Pod**|Smallest unit (container wrapper)|nginx pod|
|**Deployment**|Manage pod replicas|3 replicas of nginx|
|**Service**|Expose pods (networking)|LoadBalancer for nginx|

|**Secret**|Sensitive data|Database password|

💡 **Key Takeaway — Container Orchestration at Scale:**

Before Kubernetes:

- ❌ Manual container management
- ❌ No automatic scaling
- ❌ No self-healing
- ❌ Complex multi-node coordination

After Kubernetes:

- ✅ Declarative deployments (YAML)
- ✅ Automatic scaling (CPU/memory)
- ✅ Self-healing (restart failed containers)
- ✅ Automatic container scheduling
- ✅ Zero-downtime updates
