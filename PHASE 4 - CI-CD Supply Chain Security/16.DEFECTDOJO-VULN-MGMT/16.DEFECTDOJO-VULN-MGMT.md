## 16.1 Why DefectDojo Matters

In a complete CI/CD pipeline, vulnerabilities come from multiple sources:

|Source|Tool|Type|
|---|---|---|
|**Code**|SonarQube|SAST (bugs, injection flaws)|
|**Dependencies**|SonarQube/Snyk|Vulnerable libraries|
|**Container Images**|Harbor/Trivy|OS package vulnerabilities|
|**Infrastructure**|Various|Misconfiguration|
|**API Security**|DAST tools|Runtime vulnerabilities|

**DefectDojo** is the single pane of glass: centralizes, deduplicates, tracks, and reports.

## 16.2 Installation

### Step 1 — Create DefectDojo Directory

```bash
vm# mkdir -p /opt/defectdojo/{db,media,logs}
vm# cd /opt/defectdojo
```

### Step 2 — Create docker-compose.yml

```bash
vm# cat > docker-compose.yml << 'EOF'
version: '3.8'

services:
  defectdojo:
    image: defectdojo/defectdojo:latest
    container_name: defectdojo
    restart: always
    hostname: defectdojo.devsecops.com
    
    environment:
      DEBUG: "False"
      ENVIRONMENT: production
      SECRET_KEY: ${DJANGO_SECRET_KEY}
      DATABASE_ENGINE: django.db.backends.postgresql
      DATABASE_NAME: defectdojo
      DATABASE_USER: defectdojo
      DATABASE_PASSWORD: defectdojo_db_password
      DATABASE_HOST: postgres
      DATABASE_PORT: 5432
      CELERY_BROKER_URL: redis://redis:6379/0
      CELERY_RESULT_BACKEND: redis://redis:6379/0
      REDIS_BROKER: redis://redis:6379/0
      
      # OIDC authentication
      SOCIAL_AUTH_OIDC_ENDPOINT: http://sec-idm-01:9000/application/o/defectdojo/
      SOCIAL_AUTH_OIDC_KEY: defectdojo-oidc-client-id
      SOCIAL_AUTH_OIDC_SECRET: defectdojo-oidc-client-secret
      SOCIAL_AUTH_REDIRECT_IS_HTTPS: "False"
      
      # Email settings (optional)
      EMAIL_BACKEND: django.core.mail.backends.console.EmailBackend
    
    ports:
      - "8000:8000"
    
    volumes:
      - ./media:/app/media
      - ./logs:/app/logs
    
    depends_on:
      - postgres
      - redis
    
    networks:
      - devsecops

  postgres:
    image: postgres:14
    container_name: defectdojo-postgres
    restart: always
    
    environment:
      POSTGRES_DB: defectdojo
      POSTGRES_USER: defectdojo
      POSTGRES_PASSWORD: defectdojo_db_password
    
    volumes:
      - ./db:/var/lib/postgresql/data
    
    networks:
      - devsecops

  redis:
    image: redis:7-alpine
    container_name: defectdojo-redis
    restart: always
    
    networks:
      - devsecops

networks:
  devsecops:
    driver: bridge

EOF
```

### Step 3 — Generate Secret Key and Start

```bash
vm# export DJANGO_SECRET_KEY=$(python3 -c "import secrets; print(secrets.token_urlsafe(50))")
vm# docker-compose up -d
vm# docker-compose logs -f defectdojo  # Wait 2-3 minutes
```

### Step 4 — Create Admin User

```bash
vm# docker-compose exec -T defectdojo python manage.py createsuperuser
# Follow prompts (username: admin, email: admin@devsecops.com, password: DefectDojo123!)
```

## 16.6 Vulnerability Management

### Risk Scoring

DefectDojo calculates risk scores:

```
Risk Score = (Severity × Probability × Impact)

CRITICAL vulnerability = 9.0+ (highest)
HIGH = 7.0-8.9
MEDIUM = 4.0-6.9
LOW = 1.0-3.9

Example:
- SQL Injection (CRITICAL) = 9.5
- XSS (HIGH) = 7.8
- Log Injection (MEDIUM) = 5.2
```

### Remediation Tracking

1. **View Finding**
2. **Assign to Developer**
3. **Set Due Date**
4. **Track Status:** Open → In Progress → Resolved

### SLA Management

Define SLAs (Service Level Agreements):

```
Critical: 24 hours to fix
High: 7 days to fix
Medium: 30 days to fix
Low: 90 days to fix

DefectDojo tracks:
✅ Days since discovery
✅ Days remaining per SLA
✅ Breaches (overdue findings)
```

## 16.8 Integration with CI/CD

### Fail Pipeline if Critical Vulnerabilities

```yaml
# GitLab CI/CD
defectdojo_check:
  stage: scan
  script:
    - |
      CRITICAL=$(curl -s \
        -H "Authorization: Token $DEFECTDOJO_API_TOKEN" \
        https://defectdojo.devsecops.com/api/v2/findings/ \
        ?severity=Critical | jq '.count')
      
      if [ "$CRITICAL" -gt 0 ]; then
        echo "❌ CRITICAL vulnerabilities found: $CRITICAL"
        exit 1
      fi
  only:
    - merge_requests
```

## 16.11 Validation Script

```bash
#!/bin/bash
# ~/lab/scripts/validate-chapter-16.sh

set -euo pipefail

DEFECTDOJO_IP="10.0.2.15"
PASS=0
FAIL=0

echo "============================================="
echo " Chapter 16 Validation — DefectDojo         "
echo "============================================="

echo ""
echo "--- DefectDojo Service ---"

if ssh sec-appsec-01 'docker ps | grep -q defectdojo' 2>/dev/null; then
    echo "  ✅ PASS: DefectDojo container running"
    ((PASS++))
else
    echo "  ❌ FAIL: DefectDojo not running"
    ((FAIL++))
fi

echo ""
echo "--- Web UI Access ---"

if curl -s -k https://$DEFECTDOJO_IP:8000 2>/dev/null | grep -q -i defectdojo; then
    echo "  ✅ PASS: DefectDojo web UI accessible"
    ((PASS++))
else
    echo "  ❌ FAIL: DefectDojo web UI not responding"
    ((FAIL++))
fi

echo ""
echo "--- Results ---"
echo "  Passed: ${PASS}"
echo "  Failed: ${FAIL}"

if [ "$FAIL" -eq 0 ]; then
    echo ""
    echo "🎉 DefectDojo is operational!"
else
    echo ""
    echo "⚠️  ${FAIL} check(s) failed."
    exit 1
fi

```
