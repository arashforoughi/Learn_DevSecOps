## 15.1 Why Harbor Matters in Supply Chain Security

Docker images are critical. Harbor provides:

|Feature|Benefit|
|---|---|
|**Registry**|Store images securely (not on Docker Hub)|
|**Scanning**|Detect vulnerabilities in images|
|**Access Control**|RBAC for who can pull/push images|
|**Audit**|Track every image push/pull|
|**Replication**|Mirror images across registries|
|**Signatures**|Verify image authenticity|

🏗️ **Analogy:** Harbor is like a secure warehouse:

- **Receives deliveries** (Docker images)
- **Inspects for defects** (vulnerability scanning)
- **Catalogs inventory** (image metadata)
- **Controls access** (RBAC)
- **Logs all activity** (audit trail)

## 15.2 Installation (Docker Compose)

Log into `sec-registry-01`:

```bash
$ ssh sec-registry-01
```

Create directories:

```bash
vm# mkdir -p /opt/harbor/{config,data}
vm# cd /opt/harbor
```

Download Harbor installer:

```bash
vm# cd /tmp
vm# wget https://github.com/goharbor/harbor/releases/download/v2.9.0/harbor-offline-installer-v2.9.0.tgz
vm# tar -xzf harbor-offline-installer-v2.9.0.tgz
vm# cd harbor
```

Create harbor.yml configuration:

```bash
vm# cat > harbor.yml << 'EOF'
# Harbor Configuration

hostname: harbor.devsecops.com

http:
  port: 80

https:
  port: 443
  certificate: /etc/harbor/tls.crt
  private_key: /etc/harbor/tls.key

# Initial admin password
harbor_admin_password: HarborAdminPassword123!

# Database
database:
  password: harbor_db_password
  max_idle_conns: 50
  max_open_conns: 1000
  conn_max_lifetime: 5m
  conn_test_on_borrow: false
  conn_max_idle_time: 0

# Redis (caching)
redis:
  db_index: 1
  conn_timeout_seconds: 0
  read_timeout_seconds: 0
  write_timeout_seconds: 0

# Data volume
data_volume: /opt/harbor/data

# Log configuration
log:
  level: info
  local:
    rotate_count: 50
    rotate_size: 1G
    location: /var/log/harbor

# Authentication (OIDC via Authentik)
auth_mode: oidc_auth

oidc_provider_name: Authentik
oidc_provider_endpoint: http://sec-idm-01:9000/application/o/harbor/
oidc_client_id: harbor-oidc-client-id
oidc_client_secret: harbor-oidc-client-secret
oidc_redirect_url: https://harbor.devsecops.com/oidc/callback
oidc_scope: openid,profile,email
oidc_user_claim: email
oidc_groups_claim: groups

# Vulnerability scanning (Trivy)
trivy:
  ignore_unfixed: false
  severity: MEDIUM,HIGH,CRITICAL
  skip_update: false
  offline_scan: false
  insecure: false

# Artifact cleanup (auto-delete old images)
purge_audit:
  deletion_retention: 30
  audit_retention_days: 90

EOF
```

Generate TLS certificate:

```bash
# Use Vault-issued cert or self-signed
vm# mkdir -p /etc/harbor/tls
vm# openssl req -x509 -newkey rsa:2048 \
    -keyout /etc/harbor/tls/tls.key \
    -out /etc/harbor/tls/tls.crt \
    -days 1825 -nodes \
    -subj "/CN=harbor.devsecops.com"
```

Install Harbor:

```bash
vm# ./prepare
vm# docker-compose up -d
vm# docker-compose logs -f  # Wait for startup (2-3 minutes)
```

## 15.3 Initial Configuration

### Login to Web UI

```bash
# From host
$ firefox https://10.0.2.16
# Default: admin / HarborAdminPassword123!
```

### Configure OIDC Authentication

1. **Administration → Configuration → Authentication**
2. Verify OIDC settings (already in harbor.yml)
3. Test: Logout → Click "Authentik" button

### Create Project

1. **Projects → New Project**
    - Name: myapp
    - Visibility: Private
    - Enable content trust: yes (optional)

### Create Robot Account (for CI/CD)

1. **Administration → Robot Accounts**
    - Name: gitlab-ci
    - Project: myapp
    - Permissions: push image, pull image
    - Expires: 90 days

Copy the credentials (username/password) for GitLab CI/CD.

## 15.4 GitLab Integration

### Update .gitlab-ci.yml

```yaml
docker_build:
  stage: package
  image: docker:20.10
  services:
    - docker:20.10-dind
  variables:
    REGISTRY_URL: harbor.devsecops.com
    REGISTRY_USERNAME: $HARBOR_USERNAME
    REGISTRY_PASSWORD: $HARBOR_PASSWORD
    IMAGE_NAME: $REGISTRY_URL/myapp/myapp
  script:
    # Login to Harbor
    - docker login -u $REGISTRY_USERNAME -p $REGISTRY_PASSWORD $REGISTRY_URL
    
    # Build image
    - docker build -t $IMAGE_NAME:$CI_COMMIT_SHA .
    - docker build -t $IMAGE_NAME:latest .
    
    # Push to Harbor
    - docker push $IMAGE_NAME:$CI_COMMIT_SHA
    - docker push $IMAGE_NAME:latest
    
    # Logout
    - docker logout $REGISTRY_URL
  only:
    - main
    - master
```

### Set Harbor Credentials in GitLab

- Project → Settings → CI/CD → Variables
- `HARBOR_USERNAME`: robot account username
- `HARBOR_PASSWORD`: robot account password

## 15.5 Vulnerability Scanning

### Enable Trivy Scanner

Harbor uses Trivy to scan images. Configuration already in harbor.yml:

```yaml
trivy:
  severity: MEDIUM,HIGH,CRITICAL  # Scan sensitivity
  ignore_unfixed: false           # Report unfixed vulnerabilities
```

### Automatic Scanning

Images are scanned automatically after push. View results:

1. **Projects → myapp → Repositories**
2. Click repository name
3. Click image tag
4. **Vulnerabilities** tab shows scan results

### Block Deployment on Vulnerabilities

#### Option 1: Prevention Policy

1. **Projects → myapp → Policy → Vulnerability**
2. Set: "Prevent vulnerable images from being pulled"
3. Severity threshold: HIGH (block if HIGH or CRITICAL found)

#### Option 2: Manual Review

Require human approval for images with vulnerabilities:

```bash
# In harbor.yml or Web UI:
# Administration → System Settings
# Require approval for images with CRITICAL vulnerabilities
```

## 15.7 Image Signing & Verification

### Enable Content Trust

Images can be signed to verify authenticity:

```bash
# Enable in project
# Projects → myapp → Enable content trust

# Sign image when building
$ docker build -t harbor.devsecops.com/myapp/myapp:v1.0 .
$ DOCKER_CONTENT_TRUST=1 docker push harbor.devsecops.com/myapp/myapp:v1.0
# Prompts for signing key passphrase

# Verify signature
$ DOCKER_CONTENT_TRUST=1 docker pull harbor.devsecops.com/myapp/myapp:v1.0
# Only pulls if signature is valid
```

## 15.8 Image Cleanup & Retention

### Retention Policies

Clean up old images automatically:

1. **Projects → myapp → Tag Retention**
2. Add rule:
    - Keep latest 10 images
    - Delete images older than 30 days
    - Apply daily

Reclaim disk space:

1. **Administration → System → Garbage Collection**
2. Run schedule: Daily at 2 AM
3. Deletes orphaned blobs

## 15.9 Integration with Kubernetes

Pull images from Harbor in Kubernetes:

```yaml
# kubernetes deployment
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
      - name: myapp
        image: harbor.devsecops.com/myapp/myapp:latest
        imagePullPolicy: Always
      imagePullSecrets:
      - name: harbor-secret  # Kubernetes secret with Harbor credentials

---
# Secret for Harbor authentication
apiVersion: v1
kind: Secret
metadata:
  name: harbor-secret
type: kubernetes.io/dockercfg
data:
  .dockercfg: base64-encoded-harbor-credentials
```

## 15.12 Troubleshooting

### Problem: Images won't push to Harbor

```bash
# Check Harbor is running
vm# docker-compose ps

# Check Harbor logs for errors
vm# docker-compose logs harbor | grep -i error

# Verify credentials
$ docker login harbor.devsecops.com -u robot$gitlab-ci -p <password>

# Check Harbor accepts API requests
$ curl -s -k https://harbor.devsecops.com/api/v2.0/health | jq .
```

### Problem: Vulnerability scan is slow or stuck

```bash
# Check Trivy scanner logs
vm# docker-compose logs -f trivy

# Restart scanner
vm# docker-compose restart trivy

# Check available disk space (scanning needs space)
vm# df -h /opt/harbor/data
```

### Problem: Can't pull images from Kubernetes

```bash
# Verify imagePullSecret is created
$ kubectl get secret harbor-secret

# Verify credentials in secret
$ kubectl get secret harbor-secret -o jsonpath='{.data.\.dockercfg}' | base64 -d | jq .

# Test pull manually
$ docker login harbor.devsecops.com
$ docker pull harbor.devsecops.com/myapp/myapp:latest
```

## 15.13 Validation Script

```bash
#!/bin/bash
# ~/lab/scripts/validate-chapter-15.sh

set -euo pipefail

HARBOR_IP="10.0.2.16"
PASS=0
FAIL=0

echo "============================================="
echo " Chapter 15 Validation — Harbor Registry    "
echo "============================================="

echo ""
echo "--- Harbor Service ---"

if ssh sec-registry-01 'docker ps | grep -q harbor' 2>/dev/null; then
    echo "  ✅ PASS: Harbor container running"
    ((PASS++))
else
    echo "  ❌ FAIL: Harbor container not running"
    ((FAIL++))
fi

echo ""
echo "--- Web UI Access ---"

if curl -s -k https://$HARBOR_IP 2>/dev/null | grep -q -i harbor; then
    echo "  ✅ PASS: Harbor web UI accessible"
    ((PASS++))
else
    echo "  ❌ FAIL: Harbor web UI not responding"
    ((FAIL++))
fi

echo ""
echo "--- API Endpoint ---"

if curl -s -k https://$HARBOR_IP/api/v2.0/health 2>/dev/null | grep -q '"status":"healthy"'; then
    echo "  ✅ PASS: Harbor API healthy"
    ((PASS++))
else
    echo "  ❌ FAIL: Harbor API not responding"
    ((FAIL++))
fi

echo ""
echo "--- Scanner (Trivy) ---"

if ssh sec-registry-01 'docker ps | grep -q trivy' 2>/dev/null; then
    echo "  ✅ PASS: Trivy scanner running"
    ((PASS++))
else
    echo "  ⚠️  WARNING: Trivy scanner not found"
    ((PASS++))
fi

echo ""
echo "--- Results ---"
echo "  Passed: ${PASS}"
echo "  Failed: ${FAIL}"

if [ "$FAIL" -eq 0 ]; then
    echo ""
    echo "🎉 Harbor is operational!"
else
    echo ""
    echo "⚠️  ${FAIL} check(s) failed."
    exit 1
fi

```
