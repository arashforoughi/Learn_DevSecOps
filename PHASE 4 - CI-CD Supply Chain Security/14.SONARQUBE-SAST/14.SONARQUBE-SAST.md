## 14.1 Why Code Quality Matters in DevSecOps

Security starts with code quality. SonarQube finds:

|Type|Example|Risk|
|---|---|---|
|**Bugs**|Null pointer exception|Runtime crash|
|**Vulnerabilities**|SQL injection|Security breach|
|**Code Smells**|Duplicated code|Maintenance issues|
|**Coverage Gaps**|Untested code path|Unknown risks|

🏗️ **Analogy:** SonarQube is like a building inspector:

- **Inspects the code** (walks through, checks for issues)
- **Finds problems early** (before deployment)
- **Prevents disasters** (security, stability, maintainability)
- **Tracks progress** (quality trends over time)

## 14.2 Installation (Docker Compose)

Log into `sec-appsec-01`:

```bash
$ ssh sec-appsec-01
```

Create SonarQube directory:

```bash
vm# mkdir -p /opt/sonarqube/{data,extensions,logs,postgres_data}
vm# cd /opt/sonarqube
```

Create docker-compose.yml:

```bash
vm# cat > docker-compose.yml << 'EOF'
version: '3.8'

services:
  sonarqube:
    image: sonarqube:lts
    container_name: sonarqube
    restart: always
    hostname: sonarqube.devsecops.com
    
    environment:
      SONAR_JDBC_URL: jdbc:postgresql://postgres:5432/sonarqube
      SONAR_JDBC_USERNAME: sonarqube
      SONAR_JDBC_PASSWORD: sonarqube_db_password
      SONAR_HOST_URL: https://sonarqube.devsecops.com
      SONARQUBE_TELEMETRY_ENABLE: "false"
      SONAR_AUTH_SAML_ENABLED: "true"
      
      # LDAP authentication
      SONAR_LDAP_URL: ldap://sec-idm-01:389
      SONAR_LDAP_BINDDN: uid=service-account,ou=people,dc=devsecops,dc=com
      SONAR_LDAP_BINDPASSWORD: service_account_password
      SONAR_LDAP_USER_BASEDN: ou=people,dc=devsecops,dc=com
      SONAR_LDAP_USER_REQUEST: (&(objectClass=inetOrgPerson)(uid={login}))
      SONAR_LDAP_USER_REAL_NAME_ATTRIBUTE: cn
      SONAR_LDAP_USER_EMAIL_ATTRIBUTE: mail
      SONAR_LDAP_GROUP_BASEDN: ou=groups,dc=devsecops,dc=com
      SONAR_LDAP_GROUP_REQUEST: (&(objectClass=groupOfNames)(member={dn}))
      SONAR_LDAP_GROUP_MAPPING_ID_ATTRIBUTE: cn
      SONAR_LDAP_GROUP_MAPPING_REQUEST: (&(objectClass=groupOfNames)(member={dn}))
    
    ports:
      - "9000:9000"
    
    volumes:
      - ./data:/opt/sonarqube/data
      - ./extensions:/opt/sonarqube/extensions
      - ./logs:/opt/sonarqube/logs
    
    depends_on:
      - postgres
    
    networks:
      - devsecops

  postgres:
    image: postgres:14
    container_name: sonarqube-postgres
    restart: always
    
    environment:
      POSTGRES_DB: sonarqube
      POSTGRES_USER: sonarqube
      POSTGRES_PASSWORD: sonarqube_db_password
    
    volumes:
      - ./postgres_data:/var/lib/postgresql/data
    
    networks:
      - devsecops

networks:
  devsecops:
    driver: bridge

EOF
```

Start SonarQube:

```bash
vm# docker-compose up -d
vm# docker-compose logs -f sonarqube  # Wait for startup (1-2 minutes)
```

## 14.4 GitLab Integration

### Update GitLab CI/CD Pipeline

In your GitLab project's `.gitlab-ci.yml`:

```yaml
sonarqube:
  stage: scan
  image: sonarsource/sonar-scanner-cli:latest
  variables:
    SONAR_HOST_URL: "https://sonarqube.devsecops.com"
    SONAR_TOKEN: $SONARQUBE_TOKEN  # Set in GitLab CI/CD variables
  script:
    - sonar-scanner \
        -Dsonar.projectKey=myapp \
        -Dsonar.sources=. \
        -Dsonar.host.url=$SONAR_HOST_URL \
        -Dsonar.login=$SONAR_TOKEN \
        -Dsonar.qualitygate.wait=true
  allow_failure: true  # Allow to see results even if fails
  only:
    - merge_requests
    - main
    - master
```

### Set SONARQUBE_TOKEN in GitLab

- Project → Settings → CI/CD → Variables
- Add `SONARQUBE_TOKEN` with the token generated above

## 14.5 Quality Gates

Quality Gates define when a merge request should be blocked:

```bash
# In SonarQube Web UI:
# Administration → Configuration → Quality Gates

Create gate:
- Name: DevSecOps Lab
- Conditions:
  - Coverage < 80% (FAIL)
  - Duplicated Lines (Density) > 3% (WARN)
  - Code Smells > 100 (FAIL)
  - Bugs > 0 (FAIL)
  - Vulnerabilities > 0 (FAIL)
  - Security Hotspots > 0 (WARN)

Apply to projects:
- Projects → myapp → Quality Gates
- Select: DevSecOps Lab
```

### Enforce in GitLab

Update `.gitlab-ci.yml` to enforce quality gate:

```yaml
sonarqube:
  ...
  script:
    - sonar-scanner \
        ...
        -Dsonar.qualitygate.wait=true  # Block if quality gate fails
```

## 14.6 Security Issues Detection

### Example: SQL Injection Vulnerability

Create vulnerable code:

```python
# app.py - VULNERABLE CODE (for testing)
def get_user(user_id):
    query = f"SELECT * FROM users WHERE id = {user_id}"  # SQL INJECTION!
    return db.execute(query)
```

SonarQube detects:

- ❌ **Issue:** SQL Injection (Security Hotspot)
- **Severity:** CRITICAL
- **Message:** "User input is used directly in SQL query"
- **Fix:** Use parameterized queries

### Example: Null Pointer Exception

```python
def process_data(data):
    return data.strip()  # Bug: data could be None!
```

SonarQube detects:

- ❌ **Issue:** Potential null pointer exception
- **Severity:** MAJOR
- **Message:** "data might be None"

## 14.7 Coverage Tracking

### Add Test Coverage to Pipeline

```yaml
test:
  stage: test
  image: python:3.11
  script:
    - pip install -r requirements.txt pytest pytest-cov
    - pytest tests/ --cov=. --cov-report=xml --cov-report=term
  artifacts:
    reports:
      coverage_report:
        coverage_format: cobertura
        path: coverage.xml

sonarqube:
  ...
  script:
    - sonar-scanner \
        ...
        -Dsonar.python.coverage.reportPath=coverage.xml \
        -Dsonar.coverage.exclusions=tests/**
```

## 14.8 Security Hotspots

SonarQube identifies potential security issues that need review:

### Hotspot: Hard-coded Credentials

```python
# ❌ DANGEROUS
db_password = "MySecretPassword123"
```

SonarQube marks as **SECURITY HOTSPOT**:

- **Message:** "Hard-coded credential detected"
- **Fix:** Use Vault or environment variables

### Hotspot: Insecure Deserialization

```python
# ❌ DANGEROUS
import pickle
data = pickle.loads(user_input)  # Arbitrary code execution!
```

SonarQube marks as **SECURITY HOTSPOT**:

- **Message:** "Deserialization from untrusted source is dangerous"

## 14.11 Troubleshooting

### Problem: "Cannot connect to SonarQube"

From gitlab-runner:

```bash
# Verify connectivity
$ docker exec gitlab sonar-scanner -Dsonar.host.url=https://sonarqube.devsecops.com 2>&1 | grep -i error

# Check SonarQube is running
vm# docker-compose ps

# Check logs
vm# docker-compose logs sonarqube | grep -i error
```

### Problem: "Quality gate failed" (but want to see results)

Update `.gitlab-ci.yml`:

```yaml
sonarqube:
  ...
  allow_failure: true  # Don't block merge request, but show results
```

Then manually review SonarQube in merge request.

### Problem: LDAP authentication not working

Verify credentials:

```bash
vm# docker exec sonarqube-postgres psql -U sonarqube -d sonarqube \
    -c "SELECT * FROM users WHERE login = 'john';"
```

Test LDAP connection:

```bash
vm# ldapsearch -H ldap://sec-idm-01:389 \
    -D "uid=service-account,ou=people,dc=devsecops,dc=com" \
    -w "service_account_password" \
    -b "ou=people,dc=devsecops,dc=com" \
    uid=john
```

## 14.12 Validation Script

```bash
#!/bin/bash
# ~/lab/scripts/validate-chapter-14.sh

set -euo pipefail

SONARQUBE_IP="10.0.2.15"
PASS=0
FAIL=0

echo "============================================="
echo " Chapter 14 Validation — SonarQube          "
echo "============================================="

echo ""
echo "--- SonarQube Service ---"

if ssh sec-appsec-01 'docker ps | grep -q sonarqube' 2>/dev/null; then
    echo "  ✅ PASS: SonarQube container running"
    ((PASS++))
else
    echo "  ❌ FAIL: SonarQube container not running"
    ((FAIL++))
fi

echo ""
echo "--- Web UI Access ---"

if curl -s -k https://$SONARQUBE_IP:9000 2>/dev/null | grep -q "SonarQube"; then
    echo "  ✅ PASS: SonarQube web UI accessible"
    ((PASS++))
else
    echo "  ❌ FAIL: SonarQube web UI not responding"
    ((FAIL++))
fi

echo ""
echo "--- PostgreSQL Database ---"

if ssh sec-appsec-01 'docker ps | grep -q sonarqube-postgres' 2>/dev/null; then
    echo "  ✅ PASS: PostgreSQL running"
    ((PASS++))
else
    echo "  ❌ FAIL: PostgreSQL not running"
    ((FAIL++))
fi

echo ""
echo "--- Results ---"
echo "  Passed: ${PASS}"
echo "  Failed: ${FAIL}"

if [ "$FAIL" -eq 0 ]; then
    echo ""
    echo "🎉 SonarQube is operational!"
else
    echo ""
    echo "⚠️  ${FAIL} check(s) failed."
    exit 1
fi

```
