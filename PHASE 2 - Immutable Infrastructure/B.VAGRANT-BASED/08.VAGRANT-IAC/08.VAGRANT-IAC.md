# 8.1 What is Vagrant?

VirtualBox creates virtual machines.

Packer builds virtual machine images.

Ansible configures operating systems.

Vagrant connects all of these together.

Think of Vagrant as the **orchestrator** of your local infrastructure.

# 8.3 Why Not Just Use VirtualBox?

VirtualBox is an excellent hypervisor.

However, VirtualBox itself is **not Infrastructure as Code**.

Imagine rebuilding your laptop.

Would you like to remember:

- RAM for every VM
- CPU count
- IP addresses
- Hostnames
- Network adapters
- Boot order
- Storage controllers

Probably not.

Vagrant stores all of those settings inside a single file.

# 8.9 The Vagrantfile

The **Vagrantfile** is the heart of every Vagrant project.

Think of it as the equivalent of:

- Docker Compose for containers
- Kubernetes YAML manifests
- Ansible Playbooks
- Packer Templates

Instead of clicking through the VirtualBox interface, every virtual machine is described inside one Ruby configuration file.

Advantages include:

- Repeatable deployments
- Version control
- Easy modifications
- Team collaboration
- Infrastructure as Code

# 8.13 Automatically Creating All Virtual Machines

Instead of defining twelve virtual machines manually, Vagrant can iterate through our server list.
```ruby
Vagrant.configure("2") do |config|

  config.vm.box = "ubuntu22-golden"

  SERVERS.each do |hostname, settings|

      config.vm.define hostname do |node|

      end

  end

end
```

The loop executes once for every server.

As the infrastructure grows, no additional code is required.

# 8.15 Configure Networking

Each VM requires two network adapters.

Adapter 1:
- NAT
- Internet access

Adapter 2:
- Internal Network
- Communication between lab machines

Configure Adapter 2.
```ruby
node.vm.network "private_network",

ip: settings[:ip]
```

VirtualBox automatically creates the host-only interface if necessary.

Every machine receives a static IP address.

Example:

| Hostname | IP Address |
|------------|-------------|
| dns-01 | 10.0.2.10 |
| idm-01 | 10.0.2.11 |
| edge-01 | 10.0.2.12 |
| gitlab-01 | 10.0.2.14 |
| harbor-01 | 10.0.2.15 |

# 8.16 Configure VirtualBox Resources

Inside every VM definition:
```ruby
node.vm.provider "virtualbox" do |vb|
    vb.name = hostname
    vb.memory = settings[:ram]
    vb.cpus = settings[:cpu]
end
```

This automatically allocates the correct hardware for every server.

For example:
```
GitLab
CPU : 4
RAM : 8 GB
```

while
```
DNS
CPU : 2
RAM : 2 GB
```

# 8.17 Configure VirtualBox Settings

Disable the GUI.
```ruby
vb.gui = false
```

Enable nested virtualization.
```ruby
vb.customize [
"modifyvm",
:id,
"--nested-hw-virt",
"on"
]
```

Enable the I/O APIC.
```ruby
vb.customize [
"modifyvm",
:id,
"--ioapic",
"on"
]
```

Enable bidirectional clipboard.
```ruby
vb.customize [
"modifyvm",
:id,
"--clipboard-mode",
"bidirectional"
]
```

These settings improve compatibility and performance.

# 8.24 Lifecycle Management

One of Vagrant's biggest advantages is the ability to manage the complete lifecycle of every VM.

Start all VMs
```bash
vagrant up
```

Stop all VMs
```bash
vagrant halt
```

Suspend all VMs
```bash
vagrant suspend
```

Suspending saves RAM contents and resumes much faster than a cold boot.

Resume all VMs
```bash
vagrant resume
```

Restart all VMs
```bash
vagrant reload
```

Useful after modifying networking or VirtualBox settings.

Destroy the Lab
```bash
vagrant destroy
```

Vagrant asks for confirmation.
```text
Are you sure you want to destroy the 'dns-01' VM?
[y/N]
```

After confirmation, every VM is removed.
Because our infrastructure is defined as code, rebuilding only requires:
```bash
vagrant up
```

# 8.30 Using Snapshots

VirtualBox snapshots allow you to capture the current state of a VM before making major changes.

Create a snapshot.
```bash
vagrant snapshot save dns-01 clean-install
```

List snapshots.
```bash
vagrant snapshot list dns-01
```

Restore a snapshot.
```bash
vagrant snapshot restore dns-01 clean-install
```

Delete a snapshot.
```bash
vagrant snapshot delete dns-01 clean-install
```

Snapshots are extremely useful before installing large applications such as GitLab, Harbor, or Kubernetes.

# 8.34 Generating an Ansible Inventory

The next chapter introduces Ansible.
Instead of manually creating an inventory file, we can generate one automatically.

Create:
```text
scripts/generate_inventory.sh
```

```bash
#!/bin/bash

set -euo pipefail

cat > inventory.ini <<EOF
[dns]
dns-01 ansible_host=10.0.2.10

[idm]
idm-01 ansible_host=10.0.2.11

[edge]
edge-01 ansible_host=10.0.2.12

[vault]
vault-01 ansible_host=10.0.2.13

[gitlab]
gitlab-01 ansible_host=10.0.2.14

[harbor]
harbor-01 ansible_host=10.0.2.15

[runner]
runner-01 ansible_host=10.0.2.16

[kubernetes_master]
k8s-master-01 ansible_host=10.0.2.20

[kubernetes_workers]
k8s-worker-01 ansible_host=10.0.2.21
k8s-worker-02 ansible_host=10.0.2.22

[monitoring]
monitor-01 ansible_host=10.0.2.30

[siem]
siem-01 ansible_host=10.0.2.31

[all:vars]
ansible_user=ubuntu
ansible_python_interpreter=/usr/bin/python3

EOF

echo "inventory.ini generated successfully."
```

Make the script executable.
```bash
chmod +x scripts/generate_inventory.sh
```

Run it.
```bash
./scripts/generate_inventory.sh
```

The generated inventory will be used throughout the Ansible chapters.

# 8.37 Troubleshooting

## VirtualBox Provider Not Found

Error:
```text
The provider 'virtualbox' could not be found.
```

Verify installation.
```bash
VBoxManage --version
```

Install VirtualBox if necessary.
```bash
sudo apt install virtualbox
```

---

## Vagrant Cannot Find the Box

Verify installed boxes.
```bash
vagrant box list
```

If the box is missing, import it again.
```bash
vagrant box add ubuntu22-golden ubuntu-22.04-base.ova
```

---

## SSH Timeout

Symptoms:

- `vagrant up` hangs
- Waiting for SSH

Possible causes:

- VM still booting
- Cloud-Init not finished
- Incorrect network configuration
- SSH service failed

Check the VM console through VirtualBox and review:
```bash
sudo systemctl status ssh
```

---

## IP Address Already in Use

Symptoms:
```text
Address already assigned
```

Verify that no duplicate IP addresses exist in the `SERVERS` hash.

Use:
```bash
ip addr
```

to confirm each VM's address.

---

## Virtual Machine Already Exists

If a VM was manually created with the same name:
```text
Machine already exists.
```

Remove it from VirtualBox or rename the VM.

---

## Insufficient Memory

Symptoms:
- VM fails to boot
- Host becomes unresponsive

Reduce RAM allocations inside the `SERVERS` hash or start only the VMs required for the current chapter.

Example:
```bash
vagrant up dns-01 idm-01
```

---

## VBoxManage Errors

Always verify VirtualBox itself before troubleshooting Vagrant.
```bash
VBoxManage list vms
```

If VirtualBox cannot manage the VM, Vagrant cannot either.

# 8.38 Best Practices

- Keep the `Vagrantfile` under version control.
- Store reusable values inside variables instead of duplicating them.
- Never manually modify VM hardware in the VirtualBox GUI.
- Rebuild infrastructure from code whenever changes are required.
- Keep the Golden Image updated through Packer rather than modifying deployed VMs.
- Take snapshots before installing major services.
- Destroy and recreate development environments instead of repairing broken systems manually.
- Separate infrastructure provisioning (Vagrant) from configuration management (Ansible).

Following these practices keeps your environment predictable and reproducible.
