# Chapter 07 — Packer: Golden Image Creation with VirtualBox

## DevSecOps Lab Book — Phase 2: Immutable Infrastructure

---

> **Chapter Goal**
>
> In Chapter 01 we manually created every Ubuntu virtual machine using VirtualBox.
> Although this approach works, it is slow, error-prone, and difficult to reproduce.
>
> In this chapter we will automate the creation of our Ubuntu base image using
> **HashiCorp Packer**.
>
> Instead of installing Ubuntu manually every time, Packer will:
>
> - Download the Ubuntu ISO
> - Create a temporary VirtualBox VM
> - Install Ubuntu automatically
> - Configure the operating system
> - Install required packages
> - Apply security hardening
> - Remove temporary files
> - Export the VM as a reusable **OVA appliance**
>
> The exported appliance becomes our **Golden Image** that can later be imported
> and cloned multiple times to build the complete DevSecOps lab.

# 7.1 Why Do We Need Packer?

Imagine you have twelve Ubuntu virtual machines.

To build them manually you normally perform these steps:

1. Create a VirtualBox VM
2. Allocate CPU
3. Allocate RAM
4. Create a virtual disk
5. Mount Ubuntu ISO
6. Install Ubuntu
7. Configure networking
8. Install packages
9. Configure SSH
10. Configure Firewall
11. Install Docker
12. Apply hardening
13. Shut down
14. Clone the VM

Now imagine Ubuntu releases security updates.

You must repeat every step again.

This is not Infrastructure as Code.

---

## The Problem

Manual installation has several disadvantages.

- Human mistakes
- Different configuration on each VM
- Time consuming
- Difficult to audit
- Impossible to reproduce exactly
- Hard to update

If one administrator forgets one command, every clone will inherit that mistake.

---

## The Packer Solution

Instead of documenting installation steps, we describe the image using code.

```
Ubuntu ISO
      │
      ▼
 Packer Template (HCL)
      │
      ▼
 Temporary VirtualBox VM
      │
      ▼
 Automatic Installation
      │
      ▼
 Provisioning Scripts
      │
      ▼
 Security Hardening
      │
      ▼
 Cleanup
      │
      ▼
 Export OVA
      │
      ▼
 Golden Image
      │
      ▼
 Clone as many VMs as needed
```

The entire build process becomes deterministic.

Every image is built exactly the same way.

---

# 7.2 What is a Golden Image?

A Golden Image is a fully prepared operating system image that already contains:

- Ubuntu Server
- Updates
- Security patches
- SSH configuration
- Required packages
- Monitoring tools
- Docker prerequisites
- Time synchronization
- Security hardening

Instead of installing Ubuntu twelve times,
we install Ubuntu **once**.

Then we clone the image.

This dramatically reduces deployment time.

---

# 7.3 Immutable Infrastructure

Modern DevOps discourages changing servers manually.

Instead:

❌ Login
❌ Install packages
❌ Edit configuration
❌ Hope nothing breaks

Instead:

✔ Build new image
✔ Test image
✔ Replace old VM

This approach is called **Immutable Infrastructure**.

Packer is one of the main tools used to create immutable images.

# 7.11 Main Packer Template

Create:
```
ubuntu-22.04.pkr.hcl
```

Start by declaring the required plugin.
```hcl
packer {
  required_plugins {
    virtualbox = {
      source = "github.com/hashicorp/virtualbox"
      version = ">= 1.1.1"
    }
  }
}
```

Next, define the VirtualBox builder.
```hcl
source "virtualbox-iso" "ubuntu" {

  guest_os_type = "Ubuntu_64"

  vm_name = var.vm_name

  cpus = var.cpus

  memory = var.memory

  disk_size = var.disk_size

  headless = true

  iso_url = var.iso_url

  iso_checksum = var.iso_checksum

  communicator = "ssh"

  ssh_username = var.ssh_username

  ssh_password = var.ssh_password

  ssh_timeout = "40m"

  shutdown_command = "echo '${var.ssh_password}' | sudo -S shutdown -P now"

  output_directory = "output"

  export_opts = [
      "--manifest",
      "--ovf20"
  ]

}
```

Now define the build.
```hcl
build {

  sources = [
    "source.virtualbox-iso.ubuntu"
  ]

  provisioner "shell" {
      script = "scripts/install-packages.sh"
  }

  provisioner "shell" {
      script = "scripts/hardening.sh"
  }

  provisioner "shell" {
      script = "scripts/cleanup.sh"
  }
}
```

At this point Packer knows how to:

1. Create a VirtualBox VM
2. Install Ubuntu
3. Connect through SSH
4. Execute provisioning scripts
5. Shut down the VM
6. Export an OVA appliance

# 7.12 Unattended Ubuntu Installation

One of Packer's greatest advantages is the ability to install an operating system without any manual interaction.
Ubuntu Server supports **Autoinstall** through **Cloud-Init**.
Instead of answering installation questions manually, we provide two configuration files:

```
http/
├── user-data
└── meta-data
```

During installation, Packer starts a temporary HTTP server and serves these files to the installer.

---

# 7.13 Create Cloud-Init Files

## meta-data

Create:
```text
http/meta-data
```

Contents:
```yaml
instance-id: ubuntu-template
local-hostname: ubuntu-template
```

---

## user-data

Create:
```text
http/user-data
```

```yaml
#cloud-config

autoinstall:
  version: 1
  identity:
    hostname: ubuntu-template
    username: ubuntu
    password: "$6$ReplaceThisWithGeneratedPasswordHash"
  ssh:
    install-server: true
    allow-pw: true
  locale: en_US.UTF-8
  keyboard:
    layout: us
  timezone: UTC
  storage:
    layout:
      name: direct
  packages:
    - openssh-server
    - curl
    - wget
    - git
    - vim
  user-data:
    disable_root: true
    package_update: true
    package_upgrade: true
```

> **Note**
>
> Never store plaintext passwords inside production Packer templates.

> Use a SHA-512 password hash generated with:
>
```bash
openssl passwd -6
```

# 7.14 Boot Commands

Packer must instruct the Ubuntu installer to use our Cloud-Init files.
Inside the VirtualBox builder, add:
```hcl
http_directory = "http"
boot_wait = "5s"
boot_command = [
"<esc><wait>",
"e<wait>",
"<down><down><down><end>",
" autoinstall ds=nocloud-net;s=http://{{ .HTTPIP }}:{{ .HTTPPort }}/",
"<f10>"
]
```

During boot Packer automatically injects the kernel parameter:
```
autoinstall ds=nocloud-net
```

Ubuntu downloads the Cloud-Init files from Packer and performs a completely unattended installation.
No keyboard interaction is required.

# 7.16 Security Hardening

Create:
```
scripts/hardening.sh
```

```bash
#!/bin/bash
set -euo pipefail
echo "Applying security hardening..."
sudo timedatectl set-timezone UTC
sudo systemctl enable chrony
sudo systemctl enable auditd
sudo systemctl enable fail2ban
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw --force enable
```

---

## SSH Hardening

Append:
```bash
sudo tee /etc/ssh/sshd_config.d/hardening.conf >/dev/null <<EOF
PermitRootLogin no
PasswordAuthentication yes
PermitEmptyPasswords no
PubkeyAuthentication yes
MaxAuthTries 3
ClientAliveInterval 300
ClientAliveCountMax 2
X11Forwarding no
AllowTcpForwarding yes
EOF

sudo systemctl restart ssh
```

# 7.17 Cleanup Script

Before exporting the image we should remove temporary files.

Create:
```
scripts/cleanup.sh
```

```bash
#!/bin/bash
set -euo pipefail
echo "Cleaning image..."
sudo apt autoremove -y
sudo apt clean
sudo rm -rf /tmp/*
sudo rm -rf /var/tmp/*
sudo truncate -s 0 /etc/machine-id
sudo rm -f /var/lib/dbus/machine-id
sudo ln -s /etc/machine-id /var/lib/dbus/machine-id
sudo rm -f /etc/ssh/ssh_host_*
history -c
```

Removing the machine-id and SSH host keys ensures every clone generates its own unique identity.

# 7.26 Full Clone vs Linked Clone

VirtualBox supports two cloning methods.

## Full Clone

Advantages

- Completely independent
- Can be moved anywhere
- Safe to delete original VM

Disadvantages

- Uses more disk space
- Slower to create

---

## Linked Clone

Advantages

- Extremely fast
- Minimal storage usage

Disadvantages

- Depends on the parent VM
- Parent cannot be removed

---

For a DevSecOps lab we recommend **Full Clone**.

Although it consumes more storage, each VM becomes independent.

Install only packages required by every server.
Avoid application-specific software.

# 7.35 Troubleshooting

## Packer Cannot Find VirtualBox

Verify:
```bash
VBoxManage --version
```

If not found:
```bash
sudo apt install virtualbox
```

---

## VT-x / AMD-V Disabled

Error:
```
VT-x is not available
```

Enable hardware virtualization in your BIOS or UEFI.

---

## Build Stops Waiting for SSH

Possible causes:

- Wrong username
- Wrong password
- Cloud-init failed
- SSH service not started

Inspect the VM console.

---

## ISO Checksum Mismatch

Ubuntu periodically republishes installation images.
Download the latest SHA256 checksum.

Update:
```hcl
iso_checksum = "sha256:..."
```

---

## OVA Export Failed

Verify sufficient disk space.
```bash
df -h
```

Ensure the output directory is writable.

---

## Appliance Import Failed

Verify the appliance.
```bash
VBoxManage import output/ubuntu-22.04-base.ova
```

If necessary, rebuild the image.
