## 29.1 Why OS Hardening Matters

### Attack Surface Analysis

```
Operating System Attack Vectors:

1. KERNEL EXPLOITS
   ├─ Memory corruption vulnerabilities
   ├─ Privilege escalation flaws
   ├─ Use-after-free bugs
   └─ NULL pointer dereference

2. WEAK PERMISSIONS
   ├─ World-writable directories
   ├─ SUID binaries with vulnerabilities
   ├─ Overly permissive file ownership
   └─ Unnecessary setgid files

3. UNNEEDED SERVICES
   ├─ Listening on unnecessary ports
   ├─ Enabled but unused daemons
   ├─ Default credentials still set
   └─ Network services without auth

4. INSECURE CONFIGURATIONS
   ├─ Swap encryption disabled
   ├─ Core dumps enabled (info leak)
   ├─ ICMP redirects allowed
   ├─ IP forwarding enabled (unnecessary)
   └─ Automatic module loading

5. MISSING DEFENSES
   ├─ No ASLR (predictable addresses)
   ├─ No DEP/NX (code execution)
   ├─ No seccomp (all syscalls allowed)
   ├─ No AppArmor/SELinux (mandatory AC)
   └─ No audit logging (no forensics)

HARDENING REDUCES:
- Kernel exploit success rate by 70%+
- Privilege escalation possibilities
- Attack persistence capabilities
- Lateral movement options
```

### Defense in Depth at OS Level

```
Layer 1: FILESYSTEM HARDENING
└─ Separate partitions, mount options, permissions

Layer 2: KERNEL HARDENING
└─ Sysctl parameters, mitigations, disable unused features

Layer 3: SERVICE HARDENING
└─ Disable unnecessary services, minimal installations

Layer 4: SYSCALL RESTRICTIONS
└─ Seccomp, AppArmor, SELinux enforcing

Layer 5: MONITORING & DETECTION
└─ Auditd, file integrity, rootkit scanning

Layer 6: INCIDENT RESPONSE
└─ Logging, forensics, recovery procedures
```

## 29.3 Filesystem Hardening

### Partition Strategy

```
Recommended Partitioning:

/ (Root)
├─ System files
├─ Mount options: defaults,noexec (prevent execution in root)
└─ Size: 20GB minimum

/boot
├─ Kernel, bootloader, initramfs
├─ Mount options: nodev,nosuid,noexec
└─ Size: 1GB

/tmp (Temporary files)
├─ Application temporary data
├─ Mount options: nodev,nosuid,noexec (critical!)
├─ Size space size: 5-10GB
└─ Cleanup: Automatic (tmpwatch)

/var (Variable data)
├─ Log files, caches, databases
├─ Mount options: nodev,nosuid (no execute needed here)
└─ Size: 10-20GB

/var/log (System logs)
├─ All system, application, audit logs
├─ Mount options: nodev,nosuid,noexec
└─ Size: 10-50GB (depends on retention)

/var/tmp (Temporary files, survives reboot)
├─ Application temporary data
├─ Mount options: nodev,nosuid,noexec
└─ Size: Same as /tmp, bind mount to /tmp

/home (User home directories)
├─ User files
├─ Mount options: nodev,nosuid
└─ Size: Depends on user count

Mount Options Explained:
├─ nodev:    Block special device files
├─ nosuid:   SUID/SGID bits ignored
├─ noexec:   No executable scripts/binaries
├─ ro:       Read-only (for /boot after boot)
├─ defaults: Default mount options
└─ timeo=:   NFS timeout (if NFS mount)
```

### Filesystem Hardening Script

```bash
#!/bin/bash
# hardening-partitions.sh - Harden mount points

# 1. Remount /tmp with restrictive options
mount -o remount,nodev,nosuid,noexec /tmp
echo "tmpfs /tmp tmpfs defaults,rw,nosuid,nodev,noexec,relatime 0 0" >> /etc/fstab

# 2. Bind mount /var/tmp to /tmp
mount --bind /tmp /var/tmp
mount -o remount,nodev,nosuid,noexec /var/tmp
echo "/tmp /var/tmp none bind,defaults 0 0" >> /etc/fstab

# 3. Remount /var with restrictive options
mount -o remount,nodev,nosuid /var

# 4. Remount /var/log
mount -o remount,nodev,nosuid,noexec /var/log

# 5. Remount /boot read-only (after boot complete)
mount -o remount,nodev,nosuid,noexec /boot
echo "/boot /boot ext4 nodev,nosuid,noexec 0 0" >> /etc/fstab

# 6. Set sticky bit on shared directories
chmod a+t /tmp
chmod a+t /var/tmp

# 7. Verify
echo "=== Verification ==="
mount | grep -E "tmp|boot|var"
```

## 29.4 Kernel Hardening Parameters

### Comprehensive sysctl Configuration

```bash
#!/bin/bash
# /etc/sysctl.d/99-hardening.conf - Complete kernel hardening

cat > /etc/sysctl.d/99-hardening.conf << 'EOF'
# ============================================
# KERNEL PROTECTION & MITIGATION
# ============================================

# Hide kernel pointers from non-root
kernel.kptr_restrict = 2
  # 0: Allow all (insecure)
  # 1: Hide for non-root
  # 2: Hide for all (recommended)

# Restrict dmesg access to root
kernel.dmesg_restrict = 1
  # 0: Anyone can read dmesg
  # 1: Only root can read dmesg (recommended)

# Restrict printk messages to root
kernel.printk = 3 3 3 3
  # Format: console_loglevel default_message_loglevel minimum_console_loglevel default_console_loglevel
  # 3: KERN_ERR and higher (reduces info leaks)

# Restrict BPF to root
kernel.unprivileged_bpf_disabled = 1
  # 0: Unprivileged BPF allowed
  # 1: Only privileged processes can use BPF

# Disable unprivileged namespace creation
kernel.unprivileged_userns_clone = 0
  # 0: Only privileged users can create namespaces
  # 1: Unprivileged users can create namespaces (less secure)

# Panic on kernel oops (automatic reboot on kernel error)
kernel.panic_on_oops = 1
kernel.panic = 60
  # Restart after 60 seconds if kernel panics

# Restrict module loading
kernel.modules_disabled = 1
  # 0: Modules can be loaded/unloaded
  # 1: Modules cannot be loaded after boot
  # Note: Set after all modules loaded, makes recovery harder

# ============================================
# ADDRESS SPACE LAYOUT RANDOMIZATION (ASLR)
# ============================================

# Enable ASLR (randomize memory addresses)
kernel.randomize_va_space = 2
  # 0: Disabled
  # 1: Conservative (some randomization)
  # 2: Full (recommended, all memory randomized)

# ============================================
# MAGIC SYSRQ KEY (System Request Key)
# ============================================

# Disable SysRq (can be used for local attacks)
kernel.sysrq = 0
  # 0: Disabled (recommended)
  # 1: Enabled (dangerous)
  # 16: Only reboot (if needed)

# ============================================
# PTRACE (Process Tracing)
# ============================================

# Restrict ptrace to parent processes only
kernel.yama.ptrace_scope = 2
  # 0: Unrestricted ptrace
  # 1: Can only trace own descendants
  # 2: Can only trace own descendants (admin only)
  # 3: No ptrace except for kernel debugging

# ============================================
# SWAP (Virtual Memory)
# ============================================

# Restrict swappiness (prefer RAM)
vm.swappiness = 10
  # 0: Never swap (can cause OOM)
  # 10: Minimize swapping (recommended)
  # 100: Aggressive swapping

# Restrict VFS cache (for ASLR effectiveness)
vm.vfs_cache_pressure = 50
  # 100: Default
  # 50: Prefer memory for cache

# ============================================
# NETWORK PARAMETERS
# ============================================

# Disable SYN cookies (or enable for DDoS protection)
net.ipv4.tcp_syncookies = 1
  # 0: Disabled
  # 1: Enabled (prevents SYN flood, slight perf impact)

# TCP SYN backlog size
net.ipv4.tcp_max_syn_backlog = 2048

# Restrict ICMP redirects
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv4.conf.all.secure_redirects = 0
net.ipv4.conf.default.secure_redirects = 0
net.ipv6.conf.all.accept_redirects = 0
net.ipv6.conf.default.accept_redirects = 0

# Ignore bogus error responses
net.ipv4.icmp_ignore_bogus_error_responses = 1

# Restrict ICMP (disable ping from outside)
net.ipv4.icmp_echo_ignore_broadcasts = 1

# Enable reverse path filtering (prevent IP spoofing)
net.ipv4.conf.all.rp_filter = 1
net.ipv4.conf.default.rp_filter = 1

# Disable source packet routing
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.conf.default.accept_source_route = 0
net.ipv6.conf.all.accept_source_route = 0
net.ipv6.conf.default.accept_source_route = 0

# Disable IP forwarding (unless router)
net.ipv4.ip_forward = 0
net.ipv6.conf.all.forwarding = 0

# Log suspicious packets
net.ipv4.conf.all.log_martians = 1
net.ipv4.conf.default.log_martians = 1

# ============================================
# FILE SYSTEM
# ============================================

# Restrict file creation umask
fs.protected_symlinks = 1
fs.protected_hardlinks = 1
fs.protected_regular = 2
fs.protected_fifos = 2

# ============================================
# CORE DUMPS
# ============================================

# Disable core dumps (information leak)
kernel.core_uses_pid = 0
fs.suid_dumpable = 0

EOF

# Apply settings
sysctl -p /etc/sysctl.d/99-hardening.conf

# Verify
echo "=== Kernel Hardening Verification ==="
sysctl kernel.kptr_restrict
sysctl kernel.dmesg_restrict
sysctl kernel.unprivileged_bpf_disabled
sysctl kernel.randomize_va_space
```

## 29.5 AppArmor Mandatory Access Control

### AppArmor Profiles

```bash
# Check AppArmor status
aa-status

# View loaded profiles
cat /etc/apparmor.d/ | head -20

# Create custom profile for critical applications
cat > /etc/apparmor.d/custom/database-server << 'EOF'
#include <tunables/global>

profile database-server flags=(attach_disconnected,mediate_deleted) {
  #include <abstractions/base>
  #include <abstractions/nameservice>
  #include <abstractions/openssl>

  # Capabilities needed
  capability setuid,
  capability setgid,
  capability net_bind_service,
  capability sys_chroot,

  # Network access
  network inet stream,
  network inet dgram,
  network unix stream,
  network unix dgram,

  # File access
  /var/lib/postgresql/** rwk,
  /var/run/postgresql/** rw,
  /etc/postgresql/** r,
  /usr/lib/postgresql/** rm,
  /proc/** r,
  /sys/** r,

  # Deny dangerous operations
  deny /boot/** rwx,
  deny /sys/module/** rwx,
  deny /proc/sys/** rwx,

  # Allow ptrace only for debugging
  ptrace (read) peer=unconfined,

  # Logging
  /var/log/postgresql/** w,
}
EOF

# Load and enforce profile
apparmor_parser -r /etc/apparmor.d/custom/database-server

# Set enforce mode (default) or complain mode (logging only)
aa-enforce /etc/apparmor.d/custom/database-server
# aa-complain /etc/apparmor.d/custom/database-server  # For testing
```

## 29.6 Seccomp (Syscall Filtering)

### Understanding Syscalls

```
What is a Syscall?

DEFINITION:
├─ Interface between user space and kernel
├─ Called by applications to request kernel services
└─ Examples: open(), read(), write(), fork(), execve()

SYSCALL FLOW:
┌──────────────┐
│  Application │
└──────┬───────┘
       │
   [Syscall]
       │
┌──────▼───────────────┐
│ Seccomp Filter (if enabled)
│ ├─ Allow specific syscalls
│ └─ Block dangerous ones
└──────┬───────────────┘
       │
┌──────▼──────────────────┐
│ Kernel Space
│ Executes requested
│ kernel operation
└──────┬──────────────────┘
       │
┌──────▼───────────┐
│ Return to App
└───────────────────┘

DANGEROUS SYSCALLS TO BLOCK:
├─ ptrace() - Process tracing (escape)
├─ prctl() with specific flags - Process control
├─ execve() - Execute new binary (in containers)
├─ socket() - Networking (unless needed)
├─ open_by_handle_at() - Bypass path-based access control
├─ init_module()/delete_module() - Kernel modules
├─ ioctl() - Raw device access
├─ reboot() - System reboot
├─ syslog() - System logging
└─ sysctl() - Kernel parameter modification
```

## 29.7 Container Escape Prevention

### Pod Security Standards

```yaml
# Comprehensive pod security context
apiVersion: v1
kind: Pod
metadata:
  name: hardened-pod
  namespace: secure-apps
spec:
  # Pod-level security context
  securityContext:
    runAsNonRoot: true              # Must run as non-root
    runAsUser: 1000                 # Specific UID
    runAsGroup: 3000                # Specific GID
    fsGroup: 2000                   # For shared volumes
    seccompProfile:
      type: RuntimeDefault          # Default seccomp profile
    seLinuxOptions:
      level: "s0:c123,c456"        # SELinux level
    supplementalGroups: [4000, 5000] # Additional groups
    fsGroupChangePolicy: "OnRootMismatch" # Fix volume ownership
    sysctls:
    - name: kernel.shm_rmid_forced
      value: "1"

  serviceAccountName: app-service-account

  containers:
  - name: app
    image: myapp:latest
    imagePullPolicy: Always

    securityContext:
      # Container-level security context
      allowPrivilegeEscalation: false    # Cannot escalate privileges
      readOnlyRootFilesystem: true       # Read-only root filesystem
      runAsNonRoot: true                 # Enforce non-root
      runAsUser: 1000                    # Run as specific user
      runAsGroup: 3000                   # Run as specific group
      
      # Capabilities (drop all, add only needed)
      capabilities:
        drop:
        - ALL                           # Drop all Linux capabilities
        add:
        - NET_BIND_SERVICE             # Only if binding <1024 port
        - CHOWN                        # Only if file ownership needed
      
      # Seccomp filter
      seccompProfile:
        type: Localhost
        localhostProfile: restricted-syscalls.json

    # Resource limits (prevent resource exhaustion)
    resources:
      limits:
        cpu: 500m                      # Max 0.5 CPU
        memory: 512Mi                  # Max 512MB
      requests:
        cpu: 250m                      # Min 0.25 CPU
        memory: 256Mi                  # Min 256MB

    # Probes for health checking
    livenessProbe:
      httpGet:
        path: /health
        port: 8080
      initialDelaySeconds: 30
      periodSeconds: 10
      timeoutSeconds: 5
      failureThreshold: 3

    readinessProbe:
      httpGet:
        path: /ready
        port: 8080
      initialDelaySeconds: 5
      periodSeconds: 5
      timeoutSeconds: 3
      failureThreshold: 3

    # Volume mounts
    volumeMounts:
    - name: tmp
      mountPath: /tmp
      readOnly: false
    - name: cache
```

```bash
aa-status | head -5

ufw status
```

## 29.12 Common Hardening Challenges & Solutions

```
Challenge: Performance impact from security measures

Solutions:
├─ Profiling to identify bottlenecks
├─ Tuning parameters (swappiness, cache pressure)
├─ Using tmpfs for high-traffic temporary data
├─ SSD for database servers
├─ Load balancing across multiple nodes
└─ Monitoring and alerting for issues

Challenge: Application compatibility with restrictive settings

Solutions:
├─ Complain mode first (aa-complain for AppArmor)
├─ Gradual enforcement (start with audit, move to enforce)
├─ Custom profiles for specific applications
├─ Testing in staging environment
├─ Whitelisting instead of blacklisting
└─ Documentation of exceptions

Challenge: Managing hardening across large infrastructure

Solutions:
├─ Infrastructure as Code (Terraform/OpenTofu)
├─ Ansible playbooks for automated hardening
├─ Baseline images (Packer) with hardening baked in
├─ Compliance scanning automated (OpenSCAP)
├─ Centralized logging for all audit events
└─ Regular vulnerability assessments
```
